# Adding a solver kind — the whole system, in order

A kind is not just a function: it is wired into a manifest, a byte-identity golden snapshot, several drift
gates, two adversarial harnesses, and the public docs. Miss a step and CI fails (or worse, ships a stale
number). Do these in order. **Branch + PR + reviewer + CI + merge — never push `main` directly.**

## The tools/gates you are wiring into (know them first)

| tool / gate | file | what it enforces |
|---|---|---|
| `@kind` registry | `idm/_solve_domains/dNN_*.py` | the live set — `idm.kinds()` is the single source of truth for the count |
| capabilities manifest | `capabilities.json` (generated by `tools/gen_capabilities.py`) | machine-readable catalogue; a CI gate requires it byte-identical to a fresh regen and covering every kind exactly once |
| **golden snapshot** | `tests/golden/kind_outputs.json` (`tests/test_kernel_migration_snapshot.py`) | **byte-identity of every kind's output** on its fixture — the refactor/authority net |
| fixtures | `tests/test_properties.py` `FIXTURES` | one runnable example per kind; feeds the property + golden + differential + adversarial passes |
| differential harness | `tests/test_differential_harness.py` | every kind cross-checked vs SymPy (comparator only) — disagreement = bug |
| adversarial harness | `tests/test_adversarial_harness.py` | hostile inputs never crash; stay tier-honest (HOLD, not fake) |
| consistency gates | `tests/test_repo_consistency_gates.py` | version single-sourced; theorem count vs `verify.sh`; **kind-count single-sourced across docs (doc-scan)** |
| manifest/registry gates | `tests/test_capabilities_manifest.py`, `tests/test_kernel_p1.py` | manifest == `idm.kinds()`; kernel import doesn't disturb the registry (**no hardcoded total — do not re-introduce one**) |

## Steps

1. **Register.** In the right domain file `idm/_solve_domains/dNN_*.py`:
   ```python
   @kind("your_kind", "exact")            # tier: exact | Th_coqc | finite_diagnostic | +ℝ-Open
   def _yk(p): return _ok("your_kind", <value>, "<method>")   # or a {"status":"HOLD","reason":...} dict
   ```
   HOLD (never a fabricated answer) on missing fields / out-of-scope / uncertifiable input.
2. **Tier honesty.** `exact` only if the result is exact over ℤ/ℚ. `Th_coqc` **requires** a real
   `formal/*.v` witness (add the theorem, put the kind in `_COQ_BACKED` in `idm/solve.py`, run
   `bash formal/verify.sh`, and bump the theorem count in README/formal-README/SKILL — a gate checks it).
   Never dress a conjecture; a numeric method is `finite_diagnostic`; a non-readout is `+ℝ-Open`.
3. **Classify.** Add the kind name to the correct domain bucket in `tools/gen_capabilities.py`
   (`DOMAIN_MEMBERS`), else it silently lands in `other`.
4. **Regenerate the manifest:** `python3 tools/gen_capabilities.py` (writes `capabilities.json`).
5. **Fixture.** Add a runnable example to `FIXTURES` in `tests/test_properties.py`.
6. **Regenerate the golden snapshot** (the **gold policy** — see below):
   ```
   PYTHONPATH=. python3 -c "import json,idm; import tests.test_properties as tp; \
     json.dump({k: idm.solve(dict(kind=k, **tp.FIXTURES[k])) for k in sorted(idm.kinds())}, \
               open('tests/golden/kind_outputs.json','w'), indent=1, sort_keys=True)"
   ```
   The diff **must be additive** — only your new kind's entry. If any other kind's bytes changed, you
   changed behavior; stop and understand why.
7. **Real tests.** Add per-kind correctness tests (`tests/test_*.py`); use SymPy/mpmath as an independent
   comparator where one exists. High-value: cover degrees / rational-vs-irrational / near-degenerate /
   HOLD paths — CI-green with only "pretty" inputs is how the WP2/WP3 bugs slipped past the first pass.
8. **Sync the count (now single-sourced).** The manifest/registry gates read `len(idm.kinds())` — no
   literal to edit. The **doc-scan gate** `test_kind_count_is_single_sourced_across_docs` will fail CI
   listing every doc whose stated total is stale; update exactly those to the new count. (Do **not** add a
   new hardcoded count anywhere.)
9. **CHANGELOG** entry under `## [Unreleased]`.
10. **Verify once, then ship.** Run the affected suites + the golden snapshot (and `formal/verify.sh` only
    if you touched Coq). Then: branch → PR → **adversarial reviewer** (correctness, HOLD-not-hang, no
    float leak) → CI green → merge (reviewer before merge; the founder merges reviewer-clean CI-green PRs).

## The gold policy (golden snapshot)

`tests/golden/kind_outputs.json` is the **authority**: it pins the byte-exact output of every kind. It is
regenerated **only** on an intended, reviewed change, and the regeneration is **called out in the PR**.
A migration/refactor keeps it byte-identical (that is the proof it changed nothing observable); a new
kind adds exactly one entry; a deliberately-improved output regenerates with the change explained. Never
regenerate to "make the test pass" without understanding every changed byte.

## Non-negotiables

- **HOLD, don't hang, don't fake.** Bound expensive searches (see `FactorizationBudgetExceeded` →
  `AlgebraicHOLD` in `idm/kernel/poly/algebraic.py`) so hard inputs fail closed.
- **One continuous system.** README → SOLVER.md → API.md → capabilities.json → CHANGELOG → per-folder
  READMEs must agree; the doc-scan gate enforces the count. Update the system, not one file.
- **Tier-honest always.** The verdict (`EXACT`/`CONDITIONAL`/`HOLD`, or the `Th_coqc`/`exact`/
  `finite_diagnostic`/`+ℝ-Open` tier) is the product's warrant — never inflate it.
