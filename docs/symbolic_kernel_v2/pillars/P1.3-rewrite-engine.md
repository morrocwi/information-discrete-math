# Pattern matcher & rewrite engine

# IDM Symbolic Kernel v2 — Pillar: Pattern Matcher & Rewrite Engine

**Scope of this document.** One pillar of the v2 symbolic kernel: a central, declarative pattern-matching and term-rewriting engine that replaces the ad-hoc `if h == "pow": ...` chains currently hand-written inside `idm/symbolic.py`'s `simplify()`/`expand()`/`integrate()`. This is Phase 1 architecture only — no full implementation, no new "259th kind." Every claim below is tier-honest: nothing here is asserted `Th_coqc` unless it names a Coq theorem; where none exists it is `exact` or `finite_diagnostic`, per `idm/solve.py:785-800`.

**Grounding.** All current-code references cite the actual files read for this design: `idm/symbolic.py` (306 lines), `idm/solve.py` (828 lines, `_REG` with 258 `@kind`-decorated handlers), `idm/certified.py`, `idm/functions.py`, `idm/interval.py`, `idm/exact.py`.

## (a) Data structures

**Design decision: the expression tree is NOT replaced.** `idm/symbolic.py:8-15`'s node shapes — `Fraction`, `('var', name)`, `('add', [t,…])`, `('mul', [f,…])`, `('pow', b, e)`, `('func', name, arg)` — remain the wire format every other module already speaks (`parse`/`tostr`, `diff`, `evaluate`, `poly_coeffs`, `solve`, `taylor`, and all six `symbolic_*` kinds in `solve.py:532-552`). Replacing it would break every existing caller for no gain; the ground map's own conclusion (§6, "net assessment") is that this tree should *become* the shared kernel, not be superseded. The rewrite engine is a **new layer that operates on this existing `Expr` type**.

```python
from __future__ import annotations
from dataclasses import dataclass, field
from enum import Enum
from fractions import Fraction as Q
from typing import Any, Callable, FrozenSet, Iterator, Mapping, Optional, Sequence, Tuple, Union

Expr = Union[Q, tuple]   # the existing idm/symbolic.py tree — UNCHANGED wire format

# ---------------------------------------------------------------- pattern language ----
@dataclass(frozen=True)
class Wildcard:
    """Binds to exactly one sub-expression."""
    name: str
    type_guard: str = "any"                      # "any" | "rational" | "integer" | "var" | "func"
    predicate: Optional[Callable[[Expr, "Assumptions"], bool]] = None

@dataclass(frozen=True)
class SeqWildcard:
    """Binds to zero-or-more remaining args of an n-ary add/mul — the 'rest of the sum' slot."""
    name: str
    min_len: int = 0

@dataclass(frozen=True)
class Pattern:
    """An Expr-shaped tree whose leaves may be Wildcard/SeqWildcard instead of Q/('var',...)."""
    template: Any
    commutative: bool = True     # True for add/mul-headed patterns: match ignores argument order
    associative: bool = True     # True for add/mul-headed patterns: nested add/mul is pre-flattened

@dataclass(frozen=True)
class MatchEnv:
    bindings: Mapping[str, Expr] = field(default_factory=dict)
    seq_bindings: Mapping[str, Tuple[Expr, ...]] = field(default_factory=dict)

# ---------------------------------------------------------------- domain gating ----
class GuardVerdict(Enum):
    SAFE = "safe"; UNSAFE = "unsafe"; UNKNOWN = "unknown"   # UNKNOWN is the fail-closed default

@dataclass(frozen=True)
class Assumptions:
    """Flat, declared-fact set threaded through a rewrite — no forward-chaining (see §g)."""
    facts: FrozenSet[Tuple[str, str]] = frozenset()          # e.g. {("x","nonzero"), ("x","real_positive")}
    def holds(self, var: str, prop: str) -> bool: return (var, prop) in self.facts
    def merge(self, other: "Assumptions") -> "Assumptions": return Assumptions(self.facts | other.facts)

EMPTY_ASSUMPTIONS = Assumptions()

@dataclass(frozen=True)
class Guard:
    """A rule's domain-safety precondition. Fail-closed: anything not provably SAFE is UNKNOWN."""
    check: Callable[[MatchEnv, Assumptions], GuardVerdict]
    description: str

# ---------------------------------------------------------------- rules ----
@dataclass(frozen=True)
class Rule:
    name: str
    lhs: Pattern
    rhs: Union[Any, Callable[[MatchEnv], Expr]]   # replacement template, or a builder fn for computed rhs
    guard: Optional[Guard] = None                 # None ⇒ unconditionally safe (only for provably total ops)
    priority: int = 0                              # higher fires first among rules matching the same node
    tier: str = "exact"                            # Th_coqc | exact | finite_diagnostic | Dr
    coq_theorem: Optional[str] = None              # populated only when tier == "Th_coqc"

@dataclass(frozen=True)
class RuleSet:
    name: str                                       # e.g. "core_normalize", "distribute", "log_identities"
    rules: Tuple[Rule, ...]
    default_strategy: "Strategy" = None             # set per-family; see (c)

class Strategy(Enum):
    BOTTOM_UP = "bottom_up"    # innermost-first single pass — today's simplify()/expand() behavior
    TOP_DOWN  = "top_down"     # outermost-first — needed to try a rule before recursing into its args
    FIXPOINT  = "fixpoint"     # repeat BOTTOM_UP passes to a fixed point or max_passes
    SEARCH    = "search"       # explore multiple RuleSets/paths, keep the lowest-cost terminal result

# ---------------------------------------------------------------- cost / trace / result ----
@dataclass(frozen=True)
class CostModel:
    """The complexity function pick-by-complexity optimizes over."""
    op_weight: Mapping[str, float] = field(
        default_factory=lambda: {"add": 1.0, "mul": 1.0, "pow": 2.0, "func": 3.0})
    depth_weight: float = 0.25
    def cost(self, e: Expr) -> float: ...           # Σ op_weight[node] + depth_weight · depth

DEFAULT_COST = CostModel()

@dataclass(frozen=True)
class LoopGuardConfig:
    max_steps: int = 2000
    max_passes: int = 64
    seen_cap: int = 5000          # bound on the visited-canonical-form hash set (memory backstop)

DEFAULT_LOOP = LoopGuardConfig()

@dataclass
class TraceStep:
    rule_name: str
    before: Expr
    after: Expr
    bindings: Mapping[str, Expr]
    guard_verdict: Optional[GuardVerdict]
    tier: str

@dataclass
class RewriteResult:
    value: Expr
    trace: Tuple[TraceStep, ...]
    status: str                     # "ok" | "HOLD" | "PARTIAL"
    tier: str                       # weakest tier among fired trace steps — never inflated (see §e)
    complexity_before: float
    complexity_after: float
    reason: Optional[str] = None    # set on HOLD / PARTIAL
```

## (b) Public interface contract

These are the only entry points other pillars and `solve.py` handlers call. Signatures are chosen so that `idm/symbolic.py`'s existing public names (`parse`, `tostr`, `diff`, `simplify`, `expand`, `evaluate`, `integrate`, `poly_coeffs`, `solve`, `taylor`) **keep their current signatures and call sites in `solve.py:532-552` unchanged** — they become thin wrappers over this engine.

```python
# idm/kernel/engine.py — the new module this pillar owns

def match(pattern: Pattern, e: Expr, assumptions: Assumptions = EMPTY_ASSUMPTIONS) -> Optional[MatchEnv]:
    """First successful binding of `pattern` against the ROOT of `e`, or None."""

def match_all(pattern: Pattern, e: Expr, assumptions: Assumptions = EMPTY_ASSUMPTIONS) -> Iterator[MatchEnv]:
    """Every valid binding at the root of `e` — for commutative/associative patterns this enumerates
    permutation-assignments lazily; callers should early-exit on first SAFE-guarded hit."""

def substitute(template: Any, env: MatchEnv) -> Expr:
    """Instantiate a pattern/rhs template with a match's bindings — the inverse of match()."""

def apply_rule(rule: Rule, e: Expr, assumptions: Assumptions = EMPTY_ASSUMPTIONS
               ) -> Optional[Tuple[Expr, TraceStep]]:
    """Try `rule` once at the ROOT of `e`. Returns None if no match, or if the guard is UNSAFE/UNKNOWN."""

def rewrite(e: Expr, ruleset: RuleSet, *, strategy: Strategy = None,
            assumptions: Assumptions = EMPTY_ASSUMPTIONS, cost_model: CostModel = DEFAULT_COST,
            loop_guard: LoopGuardConfig = DEFAULT_LOOP, trace: bool = False) -> RewriteResult:
    """Apply `ruleset` over the whole tree per `strategy` (defaults to ruleset.default_strategy).
    This is the workhorse simplify()/expand()/integrate() are rehosted onto."""

def search_paths(e: Expr, rulesets: Sequence[RuleSet], *, assumptions: Assumptions = EMPTY_ASSUMPTIONS,
                  cost_model: CostModel = DEFAULT_COST, max_paths: int = 8,
                  loop_guard: LoopGuardConfig = DEFAULT_LOOP) -> RewriteResult:
    """Run each RuleSet (factor/expand/cancel/trig/special-fn family) as a candidate path, evaluate
    cost_model on each terminal, return the lowest-cost RewriteResult. The one entry point that
    satisfies 'must search among transformation paths … pick by complexity.'"""

def register_ruleset(ruleset: RuleSet) -> None: ...
def get_ruleset(name: str) -> RuleSet: ...

def canonical_key(e: Expr) -> str:
    """Deterministic ordering key for commutative matching and loop-detection hashing — this IS
    idm/symbolic.py:176's existing `_key` (== tostr), reused rather than reinvented."""

def domain_gate(prop: str, *, on: str) -> Guard:
    """Factory for the standard guards: domain_gate("nonzero", on="x"), domain_gate("positive", on="x"),
    domain_gate("integer", on="exp") — builds a Guard whose check() consults MatchEnv bindings + the
    threaded Assumptions and returns SAFE only when the fact is explicitly present (fail-closed)."""
```

## (c) Key algorithms and complexity

**1. `match()` / `match_all()` — structural pattern matching.**
Non-commutative heads (`pow`, `func`, `var`, `Fraction`) match positionally: `O(|pattern|)`. Commutative/associative heads (`add`, `mul`) are flattened first (already how `simplify()` treats nested `add`/`mul`, `idm/symbolic.py:119-124, 140-146`), then matched by backtracking assignment of the pattern's *k* fixed (non-wildcard) sub-patterns against the *n* flattened arguments, with any `SeqWildcard` absorbing the remainder. Worst case `O(n^k)`; Phase 1 caps every commutative rule at `k ≤ 3` fixed sub-patterns and pre-sorts arguments by `canonical_key()` (existing `_key`, `idm/symbolic.py:176`) so the common `k ≤ 2` rules (the bulk of algebraic identities) run in `O(n log n)` sort + linear scan. `match_all` is a lazy generator so `search_paths`/`rewrite` can stop at the first `SAFE`-guarded hit instead of enumerating all bindings.

**2. `rewrite()` bottom-up single pass** — `O(N)` node visits over an `N`-node tree, each visit trying up to `R` rules in priority order: `O(N·R·match_cost)`. This matches today's `simplify()`, which is already effectively one bottom-up recursive pass (`idm/symbolic.py:100-165`).

**3. `Strategy.FIXPOINT`** — repeats bottom-up passes with an early-exit when a full pass produces zero changes (standard term-rewriting fixpoint detection), bounded by `LoopGuardConfig.max_passes`. Typical case: `O(passes_to_fixpoint · N·R)` with `passes_to_fixpoint` small (2–3, matching how `simplify()` today needs at most a couple of recursive re-entries to fully collect like terms).

**4. Loop detection** — an `LRU`/hash set of `canonical_key(e)` states seen during `FIXPOINT`/`SEARCH`, `O(1)` amortized per step. On a repeat, stop and return the lowest-`cost_model.cost()` state seen, `status="PARTIAL"`. Beyond `seen_cap` entries, fall back to the raw `max_steps` counter alone — a documented, not hidden, tradeoff (Risk 1).

**5. `search_paths()`** — treats each registered `RuleSet` (factor / expand / cancel / trig / special-fn — Phase 1 ships 5–8 families) as one candidate path, runs bounded `rewrite()` per path, keeps the minimum-cost terminal: `O(P · rewrite_cost)` with `P` = number of registered families (small, fixed), **not** a search over rule *orderings* within a family — this is a bounded beam search, not general confluence search, and its cost is stated as such (no "finds the global minimum" overclaim).

**6. Guard evaluation** — `O(1)`–`O(|Assumptions.facts|)`: a finite predicate over a finite declared-fact set. A guard that would require deciding an unbounded property (e.g. "is this positive for all real x") returns `UNKNOWN` rather than attempting an infinite proof search — guards are always finite/decidable by construction, consistent with the readout-first floor (no continuum decision procedure is ever silently invoked).

## (e) Alignment with readout-first tiers; where HOLD is returned

- `Rule.tier ∈ {Th_coqc, exact, finite_diagnostic, Dr}` mirrors `solve.py`'s existing vocabulary (`idm/solve.py:6-12, 785-800`) and the textbook's tier ladder (`Th_coqc` / `Th_coqc+classic` / `Th_coqc-elig` / `finite_diagnostic` / `Dr` / `+ℝ-Open`, `INFORMATION_DISCRETE_MATHEMATICS.md:65-103`).
- `RewriteResult.tier` = the **weakest** tier among the fired `trace` steps — a single `Th_coqc` rule never launders the tier of an otherwise `exact`/`finite_diagnostic` rewrite. This keeps faith with, rather than fights, the honesty pass already at `idm/solve.py:816-822`, which strips unbacked `Th_coqc` down to `exact` at the registry boundary.
- `Rule.coq_theorem` is populated **only** when `tier == "Th_coqc"`, mirroring `_COQ_BACKED` (`idm/solve.py:790-800`, currently 9 entries). **Phase 1 ships zero `Th_coqc`-tagged rules in the new log/sqrt/power-splitting rulesets** — no Coq theorem exists for them yet, so they ship at `exact` (algebraically exact given the guard held) or `finite_diagnostic` (where the guard itself can only be checked numerically, e.g. via `interval.py` enclosure). No tier inflation, matching the discipline already documented at `idm/solve.py:785-789`.
- **HOLD** is returned from `rewrite()`/`search_paths()` in exactly three cases, all direct successors of the existing HOLD idioms already in the codebase (`symbolic.py:242,250`; `solve.py:274,354,544,548,569-570`; `interval.py:57,73,75,77`):
  1. **No applicable rule and no recognized terminal form** — direct successor of `_Hold("no elementary antiderivative for …")` (`idm/symbolic.py:242`). `status="HOLD"`.
  2. **A `Guard` evaluates `UNKNOWN`** on the only progress-making rule — the domain safety of `log(ab)→log a+log b`, `sqrt(ab)→√a·√b`, `(x^a)^b` splitting, etc. cannot be proven from the supplied `Assumptions`. This is the direct mechanism satisfying the mandatory instruction "identities are domain-gated … only when safe": absent an explicit fact, the guard is `UNKNOWN`, never assumed `SAFE`. `status="HOLD"` (a future sibling pillar may instead return a `Piecewise` case-split — explicitly Phase 2, see (g)).
  3. **Loop/step budget exhausted** without reaching a fixpoint → `status="PARTIAL"`, best-cost intermediate state returned with `reason="loop/step budget exhausted"` — distinguished from HOLD because a valid (if unminimized) expression is still produced, not a refusal.
- The solve.py registry's tier-honesty pass and `_COQ_BACKED` table remain the **final** authority; this pillar's rule-level tiers *feed* that pass, they do not bypass or duplicate it.

## (f) Top 3 risks and mitigations

1. **Combinatorial blow-up in commutative/associative matching** (`O(n^k)` worst case, §c.1) could hang on large sums/products. *Mitigation*: cap `k ≤ 3` fixed sub-patterns per commutative rule in Phase 1, pre-sort by `canonical_key()` before matching, and enforce `LoopGuardConfig` (`max_steps`/`max_passes`) as a hard backstop on every `rewrite()`/`search_paths()` call — no unbounded rewrite is reachable from a public entry point.

2. **Unsound guards silently producing domain-wrong rewrites** — the exact failure the "domain-GATED" requirement exists to prevent (e.g. firing `sqrt(x**2)→x` without `x≥0`, currently impossible only because no such rule exists at all per ground map §4). *Mitigation*: `Guard` defaults `UNKNOWN` (fail-closed) unless a fact is *explicitly* in `Assumptions.facts` — no inference, no "probably positive" heuristics (§g scopes out forward-chaining precisely because it would weaken this). Every new guarded rule ships with property-based counterexample tests (evaluate both sides at random rational points inside vs. outside the claimed-safe domain, using the existing exact-`Fraction` evaluation path) as a Phase-1 acceptance gate, and no rule reaches `Th_coqc` without an actual theorem in `formal/`.

3. **Engine overhead regressing hot call sites** — `taylor()` calls `simplify()` `n+1` times and `diff()` `n` times per call (`idm/symbolic.py:291-299`); if `rewrite()`'s dispatch/hash-for-loop-detection overhead is materially higher than today's direct recursive `simplify()`, this regresses. *Mitigation*: keep `diff`, `poly_coeffs`, and `solve` (linear/quadratic/rational-root) as bespoke structural functions **outside** the engine (they are not pattern-rewriting problems, per (d)); benchmark the six migrated `symbolic_*` kinds against current behavior/timing as a single-file check before merge, per the standing "no repeated full-arc audits" workflow discipline — check only the new module, run the full test suite once before the final commit.

## (g) Explicitly out of scope for Phase 1

- **Full assumption/inference kernel** — no transitive fact propagation (e.g. auto-deriving `x·y>0` from `x>0 ∧ y>0`). `Assumptions` is a flat, caller-declared fact set; guards check only directly-supplied facts. A general inference engine is a separate, later pillar.
- **`Piecewise`/case-split result type** — returning both branches of a domain-dependent identity instead of `HOLD`. Flagged as the natural Phase-2 extension once a sibling pillar (verdict/certificate contract) defines the shared representation; this pillar's `HOLD` is the correct Phase-1 refusal.
- **Rehosting the numeric string-eval seam** — `functions.math_namespace()`/`evaluate()` (`idm/functions.py:57-69`), `interval.ieval`/`_NS` (`idm/interval.py:15-25`), `solve.py`'s `_cfn`/`_CNS` (`idm/solve.py:480-486`) each independently `eval()` a raw string today (ground map §6.2's "duplicates domain-unaware evaluation logic three times"). A `kernel.to_callable(expr, names)` bridge is a real, named future seam but sits outside this pillar's declared boundary (numeric evaluation, not pattern matching/rewriting) — left as a follow-up for whichever pillar owns the symbolic↔numeric bridge.
- **Migrating `symbolic.solve()` or `poly_coeffs()`** onto the rule engine — these are decision-tree/numeric-algebraic procedures (degree-based case split, coefficient extraction), not term rewriting; they stay bespoke and only call the engine for final-result normalization.
- **New Coq theorems for the new guarded identities** — Phase 1 ships log/sqrt/power-splitting rules at `exact`/`finite_diagnostic` only; `Th_coqc` promotion per identity is separate, later work (mirrors how the 9 current `_COQ_BACKED` entries, `idm/solve.py:790-800`, were added incrementally, not all at once).
- **Node shapes beyond `symbolic.py`'s existing 6** — no matrix/quaternion/tensor pattern support; Phase 1 targets exactly `Fraction | var | add | mul | pow | func`.
- **Extending the engine to the other 252 (of 258) kinds** — the tropical-semiring path kinds, Hilbert-space kinds, number-theory kinds, etc. keep their existing bespoke Python bodies unchanged in Phase 1; this pillar proves the pattern on the 6 `symbolic_*` CAS kinds only.
