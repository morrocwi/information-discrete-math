# Assumption & domain engine

# IDM Symbolic Kernel v2 — Pillar: Assumption & Domain Engine (Phase 1 architecture)

Status: design only (no implementation). Grounded in the current `idm/` codebase as of the 2026-07-27 ground map. Tier discipline: `Th_coqc` / `exact` / `finite_diagnostic` / `Dr`, every result carries `status ∈ {ok, CERTIFIED, HOLD}`. Readout-first: every predicate, bound, and interval endpoint below is a finite rational object or an explicit "no bound asserted" sentinel — never a continuum ℝ value, never a literal `+∞`. No SAT/SMT solver, no theorem-proving engine: this is a finite closed-vocabulary predicate closure + finite rational interval arithmetic, nothing more.

Home module: **`idm/assumptions.py`** (new, flat, sits alongside `certified.py`/`exact.py` in the existing one-module-per-concern layout; re-exported through `idm/_bridge.py` + `idm/__init__.py` the same way every other submodule already is).

## (a) Data structures

All fields are finite/rational or closed-enum; no field is ever a Python `float` or an unbounded numeric `+∞`. `Q = fractions.Fraction` (the type already used throughout `symbolic.py`/`exact.py`).

```python
from __future__ import annotations
from dataclasses import dataclass, field
from enum import Enum
from fractions import Fraction as Q
from typing import Optional


# ---- closed, fixed predicate vocabulary (Phase 1: no user-defined predicates) ----
class PredKind(Enum):
    REAL              = "real"
    POSITIVE          = "positive"          # x > 0
    NEGATIVE          = "negative"          # x < 0
    NONNEG            = "nonneg"             # x >= 0
    NONPOS            = "nonpos"             # x <= 0
    NONZERO           = "nonzero"            # x != 0
    ZERO              = "zero"               # x == 0  (rare; mostly a derived contradiction target)
    INTEGER           = "integer"
    EVEN              = "even"
    ODD               = "odd"
    PRIME             = "prime"
    RATIONAL          = "rational"
    IN_INTERVAL       = "in_interval"        # params: one Interval
    SQUARE_MATRIX     = "square_matrix"      # params: (n,)
    SYMMETRIC_MATRIX  = "symmetric_matrix"
    INVERTIBLE_MATRIX = "invertible_matrix"
    POSITIVE_DEFINITE = "positive_definite"
    ORTHOGONAL_MATRIX = "orthogonal_matrix"
    CONTINUOUS_ON     = "continuous_on"      # params: one Interval; ASSERTED, never proven (see e)
    DIFFERENTIABLE_ON = "differentiable_on"  # params: one Interval; ASSERTED, never proven


@dataclass(frozen=True)
class Interval:
    """A finite rational interval description. `lo`/`hi` are Fractions or None.
    None means 'no bound asserted' — an ABSENT predicate, never a numeric +inf/-inf
    (I3/I4 discipline: infinity is a refused non-readout, not a magnitude)."""
    lo: Optional[Q] = None
    hi: Optional[Q] = None
    open_lo: bool = True
    open_hi: bool = True

    def contains(self, other: "Interval") -> bool: ...      # exact rational containment check
    def intersect(self, other: "Interval") -> Optional["Interval"]: ...   # None ⇒ empty
    def is_empty(self) -> bool: ...


@dataclass(frozen=True)
class Predicate:
    """One atomic, finite assumption about a single symbol."""
    kind: PredKind
    params: tuple = ()          # e.g. (Interval(...),) for IN_INTERVAL; (n,) for SQUARE_MATRIX
    asserted: bool = True       # True = caller/handler asserted it; False = derived by closure()


@dataclass(frozen=True)
class SymbolDomain:
    """The finite, normalized conjunction of everything currently known about one symbol."""
    preds: frozenset[Predicate] = field(default_factory=frozenset)

    def add(self, p: Predicate) -> "SymbolDomain": ...          # returns a new, normalized SymbolDomain
    def has(self, kind: PredKind) -> bool: ...
    def interval(self) -> Interval: ...                          # merged IN_INTERVAL + sign predicates
    def is_contradictory(self) -> bool: ...                      # e.g. POSITIVE ∧ NEGATIVE, or empty interval


@dataclass(frozen=True)
class AssumptionSet:
    """The full context threaded through one solve()/symbolic call: symbol name -> SymbolDomain."""
    domains: tuple[tuple[str, SymbolDomain], ...] = ()    # tuple-of-pairs, not dict, so this stays hashable

    @staticmethod
    def empty() -> "AssumptionSet": return AssumptionSet(())

    def get(self, symbol: str) -> SymbolDomain: ...              # SymbolDomain.preds=frozenset() if absent
    def with_domain(self, symbol: str, d: SymbolDomain) -> "AssumptionSet": ...
    def merge(self, other: "AssumptionSet") -> "AssumptionSet": ...   # union per symbol, then re-closure


class Verdict(Enum):
    TRUE = "TRUE"
    FALSE = "FALSE"
    UNKNOWN = "UNKNOWN"          # → caller must HOLD, never guess


@dataclass(frozen=True)
class DomainVerdict:
    verdict: Verdict
    reason: str                                    # human-readable, mirrors solve.py's "reason" idiom
    evidence: tuple[Predicate, ...] = ()            # the asserted/derived predicates that decided it


@dataclass(frozen=True)
class Branch:
    """One conditional arm of a domain-conditioned result — IDM's minimal Piecewise."""
    condition: SymbolDomain          # must be ENTAILED by the caller's AssumptionSet for this arm to fire
    value: object                    # a symbolic.py tree, a Fraction, or an mp.mpf-bearing dict
    tier: str                        # one of "Th_coqc" | "exact" | "finite_diagnostic" | "Dr"
    method: str = ""                 # short description, mirrors solve.py's "method" field


@dataclass(frozen=True)
class ConditionedValue:
    """The full result of a domain-aware rewrite/identity: a finite, capped list of branches."""
    symbol: str                                # the symbol the branches condition on
    branches: tuple[Branch, ...]               # capped at MAX_BRANCHES (see risk #2)
    default: Optional[Branch] = None           # fires if no branch.condition is entailed; None ⇒ HOLD

MAX_BRANCHES = 8
MAX_PREDS_PER_SYMBOL = 24
```

Design notes on the structures:
- `AssumptionSet` is a **tuple of pairs**, not a `dict`, specifically so it is hashable and can be used as (part of) a memoization key — `symbolic.simplify`/`diff` are already pure recursive functions on an immutable tree, so a `(expr, assumptions)` cache is a natural Phase-2 win, and Phase 1 should not foreclose it with a mutable/unhashable context type.
- `Interval`'s `lo=None`/`hi=None` is the ONLY representation of "no bound was asserted" — there is no `Interval(lo=-inf, hi=inf)` anywhere in this design; that would silently inject I3/I4.
- `Predicate.asserted` distinguishes what the caller said from what `closure()` derived, purely for debuggability (`DomainVerdict.evidence` and error messages can say "derived from X", not required for correctness).

## (b) Public interface contract

Everything below lives in `idm/assumptions.py` and is the ONLY surface other pillars/handlers touch. No other module reaches into `AssumptionSet.domains` directly.

```python
# ---- construction ----
def parse_assumptions(spec: dict[str, list[str]] | list[str]) -> AssumptionSet:
    """spec is either {'x': ['positive','integer'], 'A': ['symmetric_matrix']}
    or a flat list of mini-grammar strings ['x>0', 'n:integer', 'A:symmetric_matrix'].
    Unknown predicate name -> raises ValueError at construction (fail fast, not HOLD —
    this is a caller programming error, not a domain-uncertainty result)."""

def predicate(kind: str | PredKind, *params) -> Predicate: ...

# ---- closure & query (the core inference API every pillar consults) ----
def closure(a: AssumptionSet) -> AssumptionSet:
    """Forward-chaining fixed point over the fixed closure-rule table (see (c) alg 1).
    Idempotent: closure(closure(a)) == closure(a). Raises DomainContradiction if any
    SymbolDomain.is_contradictory() after saturation (e.g. assumed both positive and even
    negative — contradictory sign/parity is a caller error, surfaced, not silently dropped)."""

def query(a: AssumptionSet, symbol: str, pred: Predicate) -> DomainVerdict:
    """Decide TRUE / FALSE / UNKNOWN for one predicate about one symbol under `a`
    (internally closes `a` first). This is the single function every pillar calls before
    applying a domain-sensitive identity."""

def entails(a: AssumptionSet, condition: SymbolDomain, symbol: str) -> bool:
    """True iff EVERY predicate in `condition` is entailed (query==TRUE) for `symbol` under `a`.
    Convenience wrapper around query(), used by resolve()."""

# ---- the seam every domain-sensitive rewrite/identity calls ----
def safe_rewrite(rule_name: str, expr, symbol: str, a: AssumptionSet) -> Optional[ConditionedValue]:
    """Look up `rule_name` in the fixed REWRITE_RULES table (pow_pow_collapse, log_product_split,
    log_quotient_split, sqrt_square, sqrt_product_split, ...), build its ConditionedValue against
    the CURRENT expr/assumptions. Returns None if the rule doesn't apply to this expr shape at all
    (not a domain question — a pattern-match miss, same as symbolic.py's existing pattern-match
    HOLDs). Never mutates `expr` or `a`."""

def domain_of_expr(expr, a: AssumptionSet) -> AssumptionSet:
    """The IMPLICIT exclusion set of a raw symbolic.py tree (distinct from the caller's asserted
    AssumptionSet): walks the tree once collecting predicates like 'this pow's base must be
    nonzero because the exponent is negative', 'this log's argument must be positive (real branch)'.
    Returned as an AssumptionSet so it can be merged with the caller's via AssumptionSet.merge()."""

# ---- resolving a ConditionedValue against a caller's assumptions, in solve.py's own idiom ----
def resolve(cv: ConditionedValue, a: AssumptionSet) -> dict:
    """Picks the first branch whose condition is entailed by `a`; if none, tries cv.default;
    if that's also None, returns {"status": "HOLD", "reason": ...}. On a hit, returns
    {"status": "ok", "value": branch.value, "tier": branch.tier, "method": branch.method,
    "domain": <str(branch.condition)>} — same dict shape solve.py's _ok()/_readout() already
    produce, so handlers can `d = resolve(cv, a); d.setdefault(...)` and return `d` unchanged."""

class DomainContradiction(Exception): ...
```

Calling convention for the ~6 `symbolic_*` handlers in `idm/solve.py:532-552` (Phase 1 wiring target — see (d)):

## (c) Key algorithms & complexity

1. **Predicate closure (forward chaining, fixed point).** A fixed, finite rule table `RULES: list[(frozenset[PredKind], PredKind)]`, e.g. `({EVEN}, INTEGER)`, `({INTEGER}, RATIONAL)`, `({RATIONAL}, REAL)`, `({PRIME}, POSITIVE)`, `({PRIME}, INTEGER)`, `({POSITIVE}, NONZERO)`, `({POSITIVE}, NONNEG)`, `({SYMMETRIC_MATRIX, SQUARE_MATRIX}, ...)`. Rules only ADD predicates (monotone) — never remove one — so the fixed point always exists and is reached in at most `|PredKind|` passes over one symbol's predicate set. Complexity per symbol: `O(|PredKind| × |RULES|)`, both fixed small constants (Phase 1 vocabulary ≈ 20 kinds, ≈ 30 rules) → effectively O(1) per symbol, O(k) for k symbols in the AssumptionSet. No fixpoint iteration ever touches an unbounded/continuum domain — the loop bound is the vocabulary size, not a numeric tolerance.

2. **Interval merge/containment (`Interval.intersect`/`contains`).** Each symbol's sign + explicit `IN_INTERVAL` predicates normalize to at most one `Interval` (Phase 1 does not support disjoint-union intervals — see (g)). Comparing/intersecting two intervals is a handful of `Fraction` comparisons — O(1). (A future Phase-2 "finite union of k disjoint rational intervals" would be O(k log k) to merge; not needed for Phase 1's single-interval-per-symbol model.)

3. **`domain_of_expr` (implicit exclusion walk).** A single bottom-up traversal of the `symbolic.py` tree, same shape as `diff()`/`simplify()` — O(n) in tree size n. A small per-node dispatch table (`pow` with `Q` negative/non-integer exponent ⇒ emit `NONZERO`(base) or `POSITIVE`(base); `func log` ⇒ emit `NONZERO`(arg) for the `log|·|` real branch or `POSITIVE`(arg) for the strict real-log branch depending on which rewrite is being asked about; `func sqrt` ⇒ emit `NONNEG`(arg)) mirrors the existing dict-dispatch style already used in `symbolic.diff`'s `d = {...}[name]` (`idm/symbolic.py:90-95`).

4. **`query`/`entails`.** After `closure()` (already paid for once per `AssumptionSet`, memoizable since `AssumptionSet` is hashable), a single predicate lookup is `O(1)` (frozenset membership) or `O(1)` interval-containment check. `entails` over a `SymbolDomain` with `p` predicates is `O(p)`, `p` bounded by `MAX_PREDS_PER_SYMBOL`.

5. **`resolve` (branch selection).** Linear scan of `ConditionedValue.branches`, `O(b)`, `b ≤ MAX_BRANCHES = 8`. First-match semantics (branches are written in priority order by the rule author, most-specific first) — deliberately NOT a general constraint solver picking the "best" branch; this keeps behavior deterministic and auditable.

Everything above is **finite, terminating, decidable** by construction (fixed vocabulary, fixed rule table, bounded caps) — there is no search, no unification, no SAT encoding, and therefore no possibility of non-termination or exponential blowup within Phase 1's scope.

## (e) Alignment with readout-first tiers; where HOLD is returned

- **Tier default = `exact`.** `closure()`, `query()`, `domain_of_expr()`, interval containment, and `SYMMETRIC_MATRIX`/`SQUARE_MATRIX`/etc. structural checks (done by exact `Fraction`-entrywise comparison, reusing `exact.py`'s existing exact linear-algebra substrate, never iterative numeric eigenvalue estimation) are all finite, decidable, no-float computations — same class as `exact.py` and matches `solve.py`'s own convention that "exact & decidable but not individually Coq-proven" = `exact`, never `Th_coqc` by default (`idm/solve.py:785-789` docstring, already the rule for every other exact handler in the file).
- **`Th_coqc` is earned, not asserted**, exactly like today: a closure rule or rewrite identity only reaches `Th_coqc` once it has a named theorem in `formal/` and an entry in `_COQ_BACKED` (`idm/solve.py:790-800`). Phase 1 adds **zero** new `_COQ_BACKED` entries — `even ⇒ integer` is trivial to prove and a good first Phase-2 candidate; `symmetric_matrix ⇒ real-diagonalizable` is the spectral theorem and a much larger undertaking, explicitly not attempted here.
- **`HOLD` is returned, never a guess, exactly at `Verdict.UNKNOWN`.** Whenever `query()` cannot entail OR refute a needed predicate from the caller's `AssumptionSet` (e.g. asked "is x nonzero" with no assumption on `x` at all), `safe_rewrite`'s `ConditionedValue` has no entailed branch, and `resolve()` falls through to `cv.default` or to `{"status": "HOLD", "reason": "cannot determine <predicate> for <symbol> under the given assumptions"}` — the same shape `solve.py` already returns for unknown-kind and for exceptions (`idm/solve.py:806-815`), so callers don't need a new case in their error handling.
- **`+ℝ-Open` / `Dr`:** `CONTINUOUS_ON`/`DIFFERENTIABLE_ON` predicates are **asserted axioms from the caller**, never derived or proven by this pillar (proving continuity needs the ε–δ/continuum-ladder machinery — a different, much larger piece of work per the discrete-math skill's own scoping of "continuity/'smooth' over ℝ" as a later derived rung, not primitive). A branch whose condition includes `CONTINUOUS_ON` is tier-capped at whatever the caller's own claim was tagged (never silently promoted to `exact`/`Th_coqc` just because the engine successfully looked the predicate up in a frozenset — asserted-but-unproven assumptions never manufacture certainty).
- **No `+∞` ever appears as a decision input.** `Interval(lo=None, hi=None)` ("no bound asserted") is handled as an ABSENT predicate throughout `closure()`/`query()` — code paths never compare against a numeric infinity sentinel, honoring I3/I4 from the readout-first discipline (a "no-upper-bound" fact is a refused non-readout, not a magnitude to reason with).
- **Interval endpoint containment is exact ℚ comparison** (`Fraction.__lt__`/`__le__`), not a tolerance-based numeric check — so `query()` on an `IN_INTERVAL` predicate never inherits `finite_diagnostic`'s epsilon-uncertainty; it is either exactly decided or `UNKNOWN`.

## (f) Top 3 risks + mitigations

1. **Incomplete closure table → silent unsoundness.** A missing rule could cause either a spurious `HOLD` (annoying) or, worse, let an unsafe rewrite fire because a needed exclusion predicate was never derived. *Mitigation:* the rule table is monotone/additive-only (rules only ADD predicates, never retract one), so the failure mode of an incomplete table is strictly under-inference → the query defaults to `UNKNOWN` → `resolve()` HOLDs. This is the safe direction and matches the framework's existing ACCEPT/HOLD asymmetry (fail toward HOLD, never toward a wrong printed answer). Additionally: every new closure rule ships with its own pytest table test (assert both the positive entailment AND the "still UNKNOWN without the premise" negative case) before it's trusted, same discipline the repo already applies per-handler.

2. **Branch/predicate-set blowup.** A carelessly written rewrite rule could emit many overlapping `ConditionedValue.branches`, or a pathological assumption chain could grow a `SymbolDomain` without bound, degrading `resolve()`/`closure()` from "fast and auditable" to "slow and opaque." *Mitigation:* hard caps enforced at construction time — `MAX_BRANCHES = 8`, `MAX_PREDS_PER_SYMBOL = 24` — raising immediately (mirroring `symbolic._Hold`'s existing exception-based coarse-refusal pattern, `idm/symbolic.py:250`) rather than degrading silently. The predicate vocabulary itself is closed/fixed in Phase 1 (no user-defined predicates), which bounds the closure table's size a priori and makes the caps easy to reason about.

3. **A third parallel "give up honestly" idiom.** The ground map already flags two: `certified.Readout` (a class with `.status`/`.bound`/`.reason`) vs. raw `{"status": "HOLD", "reason": ...}` dicts used elsewhere (ground map §6.4). A new `DomainVerdict`/`ConditionedValue` type risks becoming a third. *Mitigation:* `DomainVerdict` and `Branch`/`ConditionedValue` are INTERNAL to `assumptions.py` — the one function that crosses the boundary to `solve.py`, `resolve()`, MUST emit the plain `status`/`reason` dict idiom `_ok()`/the unknown-kind/exception paths already use (`idm/solve.py:62-66, 806-815`), never a new class instance, and MUST reuse exactly the four existing tier strings (`Th_coqc`/`exact`/`finite_diagnostic`/`Dr`) — no fifth tier is introduced.

## (g) Explicitly OUT of scope for Phase 1

- **No general SAT/SMT/first-order inference.** Closed, fixed predicate vocabulary (`PredKind` enum); forward-chaining closure only, no unification, no arbitrary logical combination beyond the built-in `TRUE`/`FALSE`/`UNKNOWN` trichotomy per predicate.
- **No numeric-path wiring.** `functions.evaluate()`, `interval.ieval`/`_NS` are NOT modified or made domain-aware; a `kernel.domain_check(env)` advisory hook for the numeric evaluators is a named Phase-2 item, not built here. Phase 1 wires the symbolic side only.
- **No new Coq proofs / no new `_COQ_BACKED` entries.** Every Phase-1 closure rule and rewrite identity ships at tier `exact`; earning `Th_coqc` is deliberately deferred, one rule at a time, as separate follow-on work (`even ⇒ integer` and `pow_pow_collapse`-under-positivity are the smallest, most obvious first Coq targets, not attempted in this document).
- **No proving continuity/differentiability.** `CONTINUOUS_ON`/`DIFFERENTIABLE_ON` are asserted axioms only, propagated, never derived. Actually deriving them needs the ε–δ continuum-ladder machinery (a different pillar entirely, per the discrete-math skill's own scoping).
- **No disjoint-union intervals.** Each `SymbolDomain` normalizes to at most one `Interval` in Phase 1 (e.g. cannot express "x < -1 or x > 1" as a single domain) — a Phase-2 extension if a concrete `symbolic_*` need for it appears; not needed by the current six-kind migration target.
- **No cross-symbol relational constraints.** `AssumptionSet` is per-symbol only; joint constraints like `x < y` between two assumed symbols are not modeled.
- **No user-extensible predicate plugin system.** The `PredKind` enum is fixed/closed for Phase 1 to keep the closure table finite and auditable by inspection; adding a predicate is a reviewed code change, not a runtime registration API.
- **No retrofit of the other 252 (of 258) kind handlers.** Only the six `symbolic_*` kinds (`idm/solve.py:532-552`) are wired as the Phase-1 proof of concept. The public API in (b) is available to every other pillar, but migrating matrix/special/integrate-numeric/etc. handlers to call it is tracked as separate, per-kind follow-on work, not part of this document.
- **No persistence/session state.** Each `solve()` call builds a fresh `AssumptionSet` from `p.get("assume", [])`; there is no cross-call assumption cache or session context, matching `solve.py`'s existing fully-stateless-per-call design.
- **No claim of parity with a general CAS's assumption system** (e.g. SymPy's `assuming()` / `refine()`). IDM's edge here is the same as everywhere else in the repo: certificate-first, ACCEPT-HOLD, explicit tier, no silent guessing under uncertainty — not breadth of inference.
