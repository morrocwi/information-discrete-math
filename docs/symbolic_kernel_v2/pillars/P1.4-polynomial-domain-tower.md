## 0. What this pillar replaces and why

Today polynomial code is **domain-blind**: `idm/exact.py`'s `poly_add/poly_mul/poly_divmod/poly_gcd/
poly_derivative/poly_integral/poly_from_roots/rational_roots` (lines 304–337, 171–193) all hard-code
`Fraction` (ℚ) as *the* coefficient type via `_ptrim`'s `[Q(x) for x in c]`. `idm/symbolic.py`'s
`poly_coeffs`/`solve` (lines 254–287) independently re-derive coefficients from the AST, again always
ℚ. Finite-field arithmetic exists only as scattered bare-`int` functions in `idm/crypto.py`
(`modinv`, `discrete_log`, `ec_add`) and `idm/exact.py` (`tonelli_shanks`, `primitive_root`,
`legendre_symbol` — lines 253–283, 386–401) with `p` threaded by hand through every call site; there
is no `GF(p)` object. There is **no ℤ vs ℚ distinction** either (`poly_gcd` silently does field-Euclid
even though ℤ is not a field — it "works" only because every coefficient gets promoted to `Fraction`
first, masking the fact that a real ℤ[x] GCD needs content/primitive-part handling to stay in ℤ).

This pillar introduces **one parametrized kernel** — `Domain` (a ring/field protocol) + `UPoly`/`MPoly`
(polynomials built over any `Domain`) — and rehosts every existing polynomial/number-theory function
in `exact.py`/`crypto.py`/`symbolic.py`'s poly slice onto it as thin, signature-preserving adapters
with `domain=QDomain` as the default. **No existing call site in `solve.py` (258 kinds) changes its
signature.** New domain-aware power (GF(p)[x], ℚ(α)[x], multivariate, Gröbner) is additive.

## (a) Data structures

All dataclasses are `frozen=True` (polynomials are values, not mutable state — matches the
finite-discrete-rational ethos: a polynomial readout is a fixed finite tuple, never mutated in place).

```python
# idm/poly/domain.py
from __future__ import annotations
from dataclasses import dataclass
from fractions import Fraction as Q
from typing import Protocol, Optional, Any
import mpmath as mp

class Domain(Protocol):
    """A commutative ring (field iff is_field). Every concrete Domain is itself a finite readout
    description — NOT ℝ. RDomain below is a finite-precision APPROXIMATION domain, tagged accordingly,
    never claimed to be the completed reals."""
    name: str                 # e.g. "Q", "Z", "GF(7)", "Q(sqrt(2))", "R~40dps", "C"
    is_field: bool
    characteristic: int       # 0 for Q/Z/R~/C, p for GF(p)

    def zero(self) -> Any: ...
    def one(self) -> Any: ...
    def add(self, a, b): ...
    def sub(self, a, b): ...
    def mul(self, a, b): ...
    def neg(self, a): ...
    def eq(self, a, b) -> bool: ...
    def from_int(self, n: int): ...
    def div(self, a, b) -> Optional[Any]:
        """Exact division a/b if it stays in the domain, else None (never silently promotes to a
        bigger domain — a ℤ[x] GCD step that needs a non-integer quotient returns None, not a
        Fraction; caller must explicitly work in QDomain if that's wanted)."""
    def inv(self, a) -> Optional[Any]:
        """Multiplicative inverse; only meaningful if is_field. Non-field domains raise NotAField."""

@dataclass(frozen=True)
class QDomain:                     # wraps idm/exact.py's existing Fraction substrate — no behavior change
    name: str = "Q"; is_field: bool = True; characteristic: int = 0
    def zero(self): return Q(0)
    def one(self): return Q(1)
    def add(self, a, b): return Q(a) + Q(b)
    # ... sub/mul/neg/eq/from_int mirror Fraction ops
    def div(self, a, b): return None if Q(b) == 0 else Q(a) / Q(b)
    def inv(self, a): return None if Q(a) == 0 else Q(1) / Q(a)

@dataclass(frozen=True)
class ZDomain:                     # NOT a field — exercises the div()->None / is_field=False contract
    name: str = "Z"; is_field: bool = False; characteristic: int = 0
    def div(self, a, b):
        if b == 0: return None
        q, r = divmod(int(a), int(b))
        return q if r == 0 else None      # exact division only; inexact -> None, never truncate silently
    def inv(self, a): raise NotAField("Z is not a field — use content/primitive-part, not inv()")

@dataclass(frozen=True)
class GFDomain:                    # GF(p), p prime — wraps idm/crypto.py's modinv/is_prime
    p: int
    is_field: bool = True; characteristic: int = None   # set to p in __post_init__
    name: str = None                                     # set to f"GF({p})" in __post_init__
    def __post_init__(self):
        from .. import exact as X
        if not X.is_prime(self.p): raise ValueError(f"GF({self.p}): p must be prime (Phase 1: prime fields only)")
        object.__setattr__(self, "characteristic", self.p)
        object.__setattr__(self, "name", f"GF({self.p})")
    def add(self, a, b): return (a + b) % self.p
    def mul(self, a, b): return (a * b) % self.p
    def inv(self, a):
        from .. import exact as X
        return X.mod_inverse(a % self.p, self.p)          # reuses exact.py:77-80 verbatim
    def div(self, a, b):
        return None if b % self.p == 0 else (a * self.inv(b)) % self.p

@dataclass(frozen=True)
class RDomain:                     # finite-precision APPROXIMATION domain — never "the reals"
    dps: int = 40; is_field: bool = True; characteristic: int = 0
    name: str = "R~"                # tostr always renders as "R~{dps}dps" so results self-disclose non-exactness
    def add(self, a, b):
        with mp.workdps(self.dps): return mp.mpf(a) + mp.mpf(b)
    def div(self, a, b):
        with mp.workdps(self.dps):
            return None if mp.mpf(b) == 0 else mp.mpf(a) / mp.mpf(b)
    # every RDomain result MUST surface as tier finite_diagnostic downstream — see (e)

@dataclass(frozen=True)
class CDomain:                     # finite-precision complex — same non-exactness discipline as RDomain
    dps: int = 40; is_field: bool = True; characteristic: int = 0
    name: str = "C~"

@dataclass(frozen=True)
class AlgebraicNumberField:
    """Q(alpha) = Q[x]/(min_poly(x)), the algebraic-extension tower. Elements are UPoly over `base`
    of degree < deg(min_poly), always reduced mod min_poly on construction."""
    base: Domain                    # typically QDomain(); Phase 1 restricts base to a field
    min_poly: "UPoly"               # monic, over `base`; irreducibility is CHECKED not assumed (see e)
    is_field: bool = True
    characteristic: int = 0
    name: str = None                # e.g. "Q(alpha)/(x^2-2)"
    def __post_init__(self):
        if not self.min_poly.is_monic(): raise ValueError("min_poly must be monic")
        object.__setattr__(self, "name", f"{self.base.name}(alpha)/({self.min_poly})")
        # irreducibility check deferred to construction helper `make_algebraic_field()` (risk §f.3)
```

## (c) Key algorithms and complexity

| Algorithm | Domain requirement | Complexity | Notes |
|---|---|---|---|
| dense add/mul (schoolbook) | any `Domain` | O(n), O(n·m) | matches existing `exact.poly_mul`'s convolution loop (exact.py:311-315) verbatim |
| divmod (long division) | `is_field` | O(n·m) | existing `exact.poly_divmod` (exact.py:316-324) generalizes directly — its `coef = r[-1]/b[-1]` line is exactly `domain.div()` |
| pseudo-division | `ZDomain` (any integral domain) | O(n·m) with coefficient growth | multiplies remainder by `lc(b)` before each subtraction step so no fractions appear |
| Euclidean GCD | `is_field` | O(n·m) per step, O(n²) worst case | direct generalization of `exact.poly_gcd` (exact.py:325-329) |
| subresultant PRS GCD | `ZDomain` | O(n²) with content/primitive-part bookkeeping | the real algorithmic fork ℤ vs ℚ forces — content(a)=gcd of int coeffs, primitive_part = a/content; Gauss's lemma keeps result primitive |
| Yun's squarefree decomposition | `is_field`, char 0 or char > deg | O(n²) (chain of GCDs) | composes `gcd` + `divmod_` + `derivative` |
| rational root theorem | `QDomain`/`ZDomain` | O(d(a₀)·d(aₙ)) candidates × O(n) eval | = existing `exact.rational_roots` unchanged |
| Sturm sequences / real root isolation | `QDomain` | O(n²) build + O(n log(1/ε)) per bisection | finite exact sign-counting, pairs with `interval.py`'s `mp.iv` enclosures on top |
| Durand–Kerner numeric roots | any (coerced to `CDomain`) | O(n²) per iteration × finite iterations | already `analysis.poly_roots` (`solve.py:207`), unchanged, stays `finite_diagnostic` |
| distinct-degree factorization + Cantor–Zassenhaus | `GFDomain(p)`, odd prime | O(n³ log p) expected (probabilistic) | new; gated by exact re-multiplication certificate |
| Berlekamp's algorithm | `GFDomain(p)` | O(n³ + n·p) linear algebra over GF(p) | deterministic alternative; reduces to `exact.rref`/`null_space`, `Th_coqc` candidate |
| resultant via Sylvester matrix | any commutative ring, `is_field` for reused determinant | O(n³) | **directly reuses `exact.determinant`'s fraction-free Gaussian elimination** — zero new linear-algebra code needed |
| discriminant | derived | O(n³) (dominated by resultant) | `disc(a) = (-1)^(n(n-1)/2)/lc(a) · resultant(a,a')` |
| Buchberger's algorithm (Gröbner basis) | any `is_field` domain | worst-case doubly-exponential in #vars (Mayr–Meyer tight); typical case much better under `GradedRevLexOrder` | **must ship with explicit `GBBudget` from day one** — see (f.1); interface fixed Phase 1, body deferred (g) |
| multivariate reduce (division algorithm) | any `is_field` domain | O(size(G)·size(f)) per step, finitely many steps (monomial order well-founded — a finite-discrete termination fact, not a continuum limit argument) | needed by Buchberger and later `eliminate()` |
| minimal polynomial via elimination | field `base` | dominated by resultant, O(cubic in degrees) | composition of `resultant` + `squarefree_decomposition`; interface only Phase 1 |

## (e) Alignment with readout-first tiers; where HOLD is returned

- **`Th_coqc`** — reserved as today (`_COQ_BACKED`, `solve.py:790-800`). None of `poly_add`/`poly_mul`/
  `poly_gcd`/… are actually in `_COQ_BACKED` despite being decorated `"Th_coqc"` at `solve.py:279-292`
  — the tier-honesty pass (`solve.py:816-822`) silently downgrades all of them to `exact` every call.
  **Phase 1 concrete deliverable candidate**: `formal/IDM_Polynomial.v` proving `poly_add`/`poly_mul`
  exactness over ℚ (pure finite-list arithmetic, low effort given `IDM_Matrix.v`/`IDM_Certified.v`
  precedent) so those decorators stop being aspirational, closing an existing accidental (harmless)
  overclaim gap.
- **`exact`** — default for `QDomain`/`ZDomain`/`GFDomain(p)` arithmetic, GCD, resultant,
  discriminant, squarefree decomposition, and — critically — **factorization results even when the
  finding method was probabilistic** (Cantor–Zassenhaus): tier is earned by `FactorCertificate.
  verified` doing an exact re-multiplication check before the caller may report `exact`, mirroring
  the existing `is_prime`/`MR_DET_BOUND` pattern (`exact.py:31-45`, `solve.py:146-155`) where the
  **result's** decidability is decoupled from the **method's** determinism.
- **`finite_diagnostic`** — `poly_roots_numeric` (Durand–Kerner), any `RDomain`/`CDomain` result, and
  probabilistic-factorization output *before* re-multiplication verification succeeds (never claimed
  `exact` on trust).
- **`Dr`** — schematic claims about "all polynomials of this shape" not backed by a checked finite
  witness set (e.g. "Gröbner bases always terminate" stays narrative unless the specific budgeted run
  actually terminated).
- **HOLD points**:
  1. `DomainMismatch` — different `Domain` instances never silently coerced.
  2. `NotAField` — `.inv()`/field-`.div()` against `ZDomain` or an unverified `AlgebraicNumberField`.
  3. `integral()` over a non-field domain where `1/(k+1)` doesn't land back in the domain.
  4. `groebner_basis`/`eliminate` `GBBudget` exhaustion → HOLD with partial basis + reason, matching
     the repo's existing "no continuum call ever produces the answer... unknown/failure returns HOLD,
     never a crash" ethos (`solve.py:1-12`) — here the "continuum" analogue is unbounded combinatorial
     search.
  5. `factor()` where no Phase-1 algorithm exists for the domain/degree (full ℤ[x] irreducible
     factorization; any factorization at all over `RDomain`/`CDomain`) → HOLD "not yet implemented",
     never a partial/wrong factor list.
  6. `make_algebraic_field()` when `min_poly` fails even the cheap squarefreeness pre-check.
  7. "Find the real number √2" style requests are refused at the interface: the only real-root
     readout is `real_root_isolate`'s exact-ℚ-endpoint interval tuple, consistent with the D→ℤ→ℚ→ℝ
     ladder in `textbook/INFORMATION_DISCRETE_MATHEMATICS.md` — ℝ is a readout of the discrete root,
     never silently assumed complete.

## (f) Top 3 risks + mitigations

1. **Gröbner basis combinatorial blowup** (Buchberger worst-case doubly exponential, Mayr–Meyer
   tight) — can hang/exhaust memory on innocuous input. *Mitigation*: mandatory `GBBudget` (max
   S-pairs / max degree / wall-clock) from day one with HOLD-on-exhaustion contract fixed in Phase 1
   even though the algorithm body is Phase 2; default `GradedRevLexOrder`; doubly-exponential worst
   case documented as a `Dr` fact in the module docstring.

2. **Migration breaks the 258 existing kind call sites.** `solve.py:202-207,279-292,585-589` and
   `symbolic.py:283-287` call today's flat-list `exact.py` functions directly. *Mitigation*: Layer 1
   (section b) is a hard invariant — every `exact.py` function name/signature preserved byte-for-byte;
   new kernel lives purely additively under `idm/poly/`. Regression check: a single-file assertion
   (`exact.poly_add([1,2],[3,4]) == [4,6]`) post-refactor — matches this workspace's "check only the
   changed file" iteration discipline.

3. **Tier inflation from probabilistic/heuristic algorithms** (Cantor–Zassenhaus; unverified
   irreducibility of a user-supplied `min_poly` producing a fake "field" with silent zero-divisors).
   *Mitigation, factorization*: `FactorCertificate.verified` (exact re-multiplication check) is
   mandatory before tier can exceed `finite_diagnostic`, mirroring `is_prime`/`MR_DET_BOUND`.
   *Mitigation, algebraic field*: Phase 1 runs the cheap squarefreeness gate (necessary, not
   sufficient) and discloses that full irreducibility was not independently re-verified; a caller
   that later hits a non-invertible nonzero element gets `NotAField`/HOLD on use rather than silent
   wrong arithmetic — honesty burden pushed to detection-on-use, not false certification-on-construction.

## (g) Explicitly OUT of scope for Phase 1

- Full Buchberger Gröbner-basis algorithm body (interface/`GBBudget`/HOLD contract only).
- Elimination-ideal computation body (`eliminate()` — interface only).
- Full irreducible factorization over ℤ[x]/ℚ[x] (Zassenhaus lifting/LLL) — Phase 1 ships squarefree
  decomposition (exact, self-verifying) and rational-root extraction only; anything beyond that is
  `NotYetImplemented`.
- Multivariate polynomial factorization (arithmetic + reduction + the Gröbner interface only).
- `minimal_polynomial()` and general algebraic-number arithmetic pipeline body (interface only —
  resultant/discriminant primitives it needs are in scope, so Phase 2 is composition not research).
- Sparse-GCD algorithms (Zippel, EEZ) — `MPoly` keeps a sparse `dict` representation from day one, but
  Phase 1 GCD/factor on it falls back to dense-style algorithms.
- FFT/Karatsuba fast multiplication — schoolbook `O(n·m)` only.
- Non-prime-modulus finite rings (`Z/nZ`, composite `n`) as a `Domain` — `GFDomain` restricted to
  prime `p` (verified via `exact.is_prime` at construction); RSA's composite-modulus arithmetic in
  `crypto.py` is deliberately left untouched.
- `RDomain`/`CDomain` factorization of any kind (no finite-decidable notion at fixed precision — root
  isolation/numeric approximation is the only honest readout there).
- Real algebraic number **arithmetic** (composing isolating intervals across two different
  polynomials) — Phase 1 ships `real_root_isolate` for a single polynomial only.
- Migration of `char_poly`/`eigenvalues`/`hermite_normal_form`/`smith_normal_form` onto `Domain` —
  flagged as Phase-2 cross-pillar item to keep this pillar's Phase-1 blast radius to `exact.py`'s
  polynomial slice plus new additive `idm/poly/` modules.
