## (a) Data structures

### a.1 The expression tree — immutable, structurally hashed, canonically ordered

Every node is a frozen, `slots`-based dataclass. Hashing and a canonical order-key are computed once at construction (`__post_init__`, written via `object.__setattr__` since the dataclass is frozen) and cached — this is the concrete answer to "structural hashing" and "canonical ordering" in the brief.

```python
# idm/kernel/nodes.py
from __future__ import annotations
from dataclasses import dataclass, field
from enum import Enum
from typing import Tuple, Optional, Mapping

class Tier(str, Enum):
    TH_COQC = "Th_coqc"
    EXACT = "exact"
    FINITE_DIAGNOSTIC = "finite_diagnostic"
    R_OPEN = "+R-Open"        # textbook §0.5.5 tier; solve.py's dispatcher only knows the first three —
                               # a node tagged R_OPEN must present as HOLD at the solve.py boundary, never
                               # as a fourth status string the dispatcher doesn't understand.

class Expr:
    """Abstract base. Every concrete node is frozen + slots; __post_init__ fills:
         _hash   : int   — structural hash over (type tag, children's structural hashes, leaf payload)
         _order  : tuple — canonical order key, see §c.2
       Both are computed bottom-up so construction cost is O(1) given already-built children."""
    __slots__ = ()
    _hash: int
    _order: tuple
    is_nonreadout: bool = False   # overridden True on Undefined / Infinity / ComplexInfinity (§a.1, Appendix A)

    def __hash__(self): return self._hash
    def __eq__(self, other):
        # hash-consing (hashcons.py) makes structurally-equal subtrees the SAME object, so this reduces
        # to `self is other` after interning — see §c.1.
        return self is other or (type(self) is type(other) and self._hash == other._hash and
                                  self._struct_eq(other))

# ---- number / symbol leaves ----
@dataclass(frozen=True, slots=True)
class Const(Expr):
    value: "Number"            # ZZ | QQ | AlgebraicNumber | ComplexExact — see numbers.py (§a.2)

@dataclass(frozen=True, slots=True)
class Symbol(Expr):
    name: str
    assumptions: "Assumptions" = field(default_factory=lambda: Assumptions())

# ---- explicit non-readout leaves — NEVER produced silently (Appendix A: Z1, I3/I4) ----
@dataclass(frozen=True, slots=True)
class Undefined(Expr):
    reason: str
    is_nonreadout: bool = True

@dataclass(frozen=True, slots=True)
class Infinity(Expr):
    sign: int                  # +1 / -1 — a SYMBOLIC placeholder for a limit statement's direction of
                                # approach, never a numeric value; see §e.
    is_nonreadout: bool = True

@dataclass(frozen=True, slots=True)
class ComplexInfinity(Expr):
    is_nonreadout: bool = True

# ---- algebraic structure ----
@dataclass(frozen=True, slots=True)
class Add(Expr):
    args: Tuple[Expr, ...]     # canonically sorted (§c.2), n-ary — same shape as symbolic.py's ('add',[t,…])

@dataclass(frozen=True, slots=True)
class Mul(Expr):
    args: Tuple[Expr, ...]

@dataclass(frozen=True, slots=True)
class Pow(Expr):
    base: Expr
    exp: Expr

@dataclass(frozen=True, slots=True)
class Func(Expr):
    name: str                  # "sin"/"cos"/"tan"/"exp"/"log"/"sqrt"/"abs"/"erf"/"gamma"/… — open registry,
    args: Tuple[Expr, ...]     # not a hardcoded literal set (fixes symbolic.py's closed FUNCS set at
                                # symbolic.py:19 so a new kind can register a function without editing the core)

# ---- relations / logic (net-new — absent from symbolic.py entirely) ----
class RelOp(str, Enum):
    EQ = "=="; NE = "!="; LT = "<"; LE = "<="; GT = ">"; GE = ">="

@dataclass(frozen=True, slots=True)
class Relation(Expr):
    op: RelOp
    lhs: Expr
    rhs: Expr

@dataclass(frozen=True, slots=True)
class BoolOp(Expr):
    op: str                    # "and" | "or" | "not" | "implies"
    args: Tuple[Expr, ...]

# ---- sets / intervals / domains (net-new) ----
@dataclass(frozen=True, slots=True)
class IntervalSet(Expr):       # named IntervalSet, not Interval, to avoid clashing with idm.interval module
    lo: Expr; hi: Expr
    lo_closed: bool; hi_closed: bool

@dataclass(frozen=True, slots=True)
class FiniteSet(Expr):
    elements: Tuple[Expr, ...] # Phase 1: FINITE discrete sets only — no set-builder over an uncountable
                                # domain (Appendix A: "real number ℝ/completeness" is a non-readout; a
                                # symbolic set of that cardinality is refused, not silently represented)

# ---- piecewise — the domain-safety escape valve (net-new, closes the "no Piecewise anywhere" gap) ----
@dataclass(frozen=True, slots=True)
class Piecewise(Expr):
    branches: Tuple[Tuple[Expr, Expr], ...]   # (value_expr, condition_expr) pairs, first true wins
    otherwise: Optional[Expr] = None           # None ⇒ Undefined("outside all declared branches") outside
                                                 # every condition — NEVER silently 0

# ---- calculus AS NODES (net-new — the brief's explicit requirement) ----
@dataclass(frozen=True, slots=True)
class Derivative(Expr):
    expr: Expr; var: Symbol; order: int = 1

@dataclass(frozen=True, slots=True)
class Integral(Expr):
    expr: Expr; var: Symbol
    lower: Optional[Expr] = None   # both None ⇒ indefinite (an antiderivative FAMILY, +C implicit — not
    upper: Optional[Expr] = None   # a value; matches symbolic.integrate's existing indefinite contract)

@dataclass(frozen=True, slots=True)
class Sum(Expr):
    expr: Expr; var: Symbol; lower: Expr; upper: Expr   # upper == Infinity(+1) is REPRESENTABLE but stays
                                                          # UNEVALUATED unless a certified.* bridge closes it

@dataclass(frozen=True, slots=True)
class Product(Expr):
    expr: Expr; var: Symbol; lower: Expr; upper: Expr

@dataclass(frozen=True, slots=True)
class Limit(Expr):
    expr: Expr; var: Symbol; point: Expr; direction: str = "both"   # "+" | "-" | "both"
    # A Limit node is a finite, exact DESCRIPTION of an open computation (Appendix A: h→0 is I2, a
    # non-readout injection). It is never auto-evaluated to a landed value. See §e.

# ---- matrix/vector/tensor as symbolic objects (net-new) ----
@dataclass(frozen=True, slots=True)
class Matrix(Expr):
    rows: int; cols: int
    data: Tuple[Expr, ...]     # row-major, length rows*cols; entries are arbitrary Expr (symbolic OK)

@dataclass(frozen=True, slots=True)
class Vector(Expr):
    data: Tuple[Expr, ...]

@dataclass(frozen=True, slots=True)
class Tensor(Expr):
    shape: Tuple[int, ...]
    data: Tuple[Expr, ...]     # flat row-major; Phase 1 ships the container only (§g)
```

### a.2 The exact number tower

```python
# idm/kernel/numbers.py
from fractions import Fraction as Q
from dataclasses import dataclass
from typing import Tuple, Union

ZZ = int            # no new wrapper — Python int already IS the exact-ℤ readout; wrapping it buys nothing
QQ = Q              # alias of fractions.Fraction — the SAME type symbolic.py and exact.py already use;
                     # Const.value keeps using the type every other module already imports as `Q`/`Fraction`

@dataclass(frozen=True, slots=True)
class AlgebraicNumber:
    """An exact real algebraic number: a root of an exact-ℚ-coefficient polynomial, identified
    unambiguously by an ISOLATING interval (no two roots of the min-poly share an isolating interval).
    Phase 1 scope: constructed ONLY from the existing quadratic-radical path (SYM.solve's discriminant
    case) and from exact.rational_roots — i.e. degree ≤ 2 exact, or an exact rational root of any degree.
    General degree-≥3 isolation (Sturm sequences) is explicitly OUT of Phase 1 — see §g."""
    min_poly: Tuple[QQ, ...]     # coefficients low-to-high, exact — same convention as exact.py's poly_* family
    lo: QQ; hi: QQ                # isolating interval, rational endpoints (refinable via idm.interval)

    def refine(self, tol: QQ) -> "AlgebraicNumber": ...   # bisection via exact.poly_eval sign changes;
                                                             # O(d) per step, see §c.5
    def sign(self) -> int: ...
    def compare(self, other: "AlgebraicNumber") -> int: ...

@dataclass(frozen=True, slots=True)
class ComplexExact:
    """Exact complex number over ℚ or AlgebraicNumber components — a Gaussian-rational-or-algebraic pair.
    Phase 1: constructed only from exact quadratic solve with negative discriminant (i.e. what
    SYM.solve already produces as a *string* `sqrt(negative)`, now representable as a first-class value
    instead of a string the caller has to re-parse)."""
    re: Union[QQ, AlgebraicNumber]
    im: Union[QQ, AlgebraicNumber]

Number = Union[ZZ, QQ, AlgebraicNumber, ComplexExact]
```

### a.3 Assumptions and Domain

```python
# idm/kernel/assumptions.py
from dataclasses import dataclass, replace
from typing import Optional

@dataclass(frozen=True, slots=True)
class Assumptions:
    """Tri-state per property: None = unknown (NOT False), True, False. Unknown must never be treated
    as False — that is exactly the silent-injection failure mode Appendix A warns about."""
    real: Optional[bool] = None
    positive: Optional[bool] = None
    negative: Optional[bool] = None
    nonzero: Optional[bool] = None
    integer: Optional[bool] = None
    rational: Optional[bool] = None

    def merge(self, other: "Assumptions") -> "Assumptions": ...   # conjunction; conflicting True/False on
                                                                     # the same field ⇒ raises (caller error,
                                                                     # not silently resolved)
    def implies_nonzero(self) -> Optional[bool]: ...
    def implies_nonnegative(self) -> Optional[bool]: ...

@dataclass(frozen=True, slots=True)
class Domain:
    """A finite conjunction of Relation constraints over Symbols — the object domain_of() returns and
    Piecewise conditions are built from. NOT a general theorem prover (see §g) — a fixed rule table."""
    constraints: Tuple["Relation", ...]

    def entails(self, rel: "Relation") -> Optional[bool]:
        """True/False only when the fixed rule table DECIDES it; None (undecided) otherwise — None must
        make the caller HOLD or emit Piecewise, never guess True."""
```

## (c) Key algorithms and complexity

**c.1 Hash-consing / structural hashing.** Each node's `_hash` is computed bottom-up from `(type_tag, children._hash..., leaf_payload)` at construction — O(1) given built children, O(n) for a whole fresh tree of n nodes. A request-scoped intern table `Dict[int, Expr]` (keyed by hash, resolved by `_struct_eq` on collision) makes structurally-equal subtrees the *same object*, so equality becomes `is` after interning (O(1)) and repeated subexpressions (common in `diff`/`expand` output) share memory instead of duplicating. Table is **request-scoped, not process-global** — see risk §f.2.

**c.2 Canonical ordering.** `Add`/`Mul` operands are sorted by a precomputed `_order` key: `(type_rank, structural_hash, …)` — O(1) comparison per pair, O(n log n) per sort. This replaces `symbolic.py`'s `_key(e) = tostr(e)` (`symbolic.py:176`), which renders a full string per comparison — O(size) per key, making like-term collection in `simplify`'s `add`/`mul` branches (`symbolic.py:128-131, 152-155`) effectively O(n·k) for tree size k. Structural-hash keys make it O(n) amortized.

**c.3 `simplify`/`expand`.** Same recursive bottom-up shape as today (`symbolic.py:100-165, 180-201`): O(n) node visits for `simplify`. `expand` is inherently worst-case exponential in output size (`(a+b)^12` → up to 4096 monomials) — same risk the current code already has at `symbolic.py:187-192` (`1 ≤ ex ≤ 12` guard exists there today, but only for `expand`'s literal-integer-power case, not for nested products of large sums generally). Kernel makes the budget explicit and load-bearing (`max_terms` param, `ResourceBudgetExceeded`) rather than an implicit magic constant.

**c.4 `diff`.** Linear O(n) tree walk (`symbolic.py:71-96` shape, unchanged). Repeated `order=k` application is O(n·k) *with* hash-consing sharing common subexpressions across derivative steps; without it, naive chain-rule expansion at high order is O(n·2^k) in the worst case (the same blow-up SymPy and every other CAS manages the same way).

**c.5 `domain_of`/assumption propagation.** Single post-order tree walk, O(n): a fixed per-node-type rule table (e.g. `Func("log", a)` requires `a > 0`; `Func("sqrt", a)` requires `a ≥ 0`; `Pow(b, e)` with non-integer `e` requires `b ≥ 0` unless `assumptions_of(b)` already proves it) — O(1) lookup per node.

**c.6 `AlgebraicNumber.refine`/`compare`.** Bisection on the isolating interval using `exact.poly_eval` (Horner, O(d) per evaluation, d = polynomial degree) reusing `idm.interval`'s bisection pattern (`interval.py:50-80`, `certified_root`) — O(d·log(1/tol)) per refinement to tolerance `tol`.

**c.7 `to_callable`.** A recursive tree-walk interpreter, same performance class as `functions.evaluate`'s current `eval(compile(...))` approach (`functions.py:66-69`) — not a compiler (see §g).

## (e) Readout-first tier alignment

Kernel's `Expr` tree is finite-discrete-rational *at the syntax level by construction* — the same commitment `symbolic.py` already has (`Const` wraps `Fraction`/`QQ`, never a `float`; textbook §0.1 Pr 0.1).

| Textbook non-readout (Appendix A) | Kernel handling |
|---|---|
| real number ℝ / completeness | `AlgebraicNumber`/exact `QQ` only; a bare `ℝ`-completeness claim is never constructed — an irrational like `sqrt(2)` stays the `Expr` `Func("sqrt", Const(2))` (a finite description) unless/until isolated as an `AlgebraicNumber` with an exact rational bounding interval. |
| the point (`r=0`) | N/A to this pillar (geometry pillar's concern) — noted for interface consistency with `IDM_Geometry.v`'s orientation predicates. |
| zero as occupied / `+∞` / `N→∞` | `Undefined()`, `Infinity(sign)`, `ComplexInfinity()` are **explicit tagged leaves**, `is_nonreadout = True`. `Pow(Const(0), Const(-1))` constructs `Undefined("division by zero")`, never a bare `inf`. |
| infinite divisibility `h→0` | `Limit` nodes never auto-evaluate. `evaluate()` on a bare `Limit` returns HOLD unless closed by `certified.richardson` — the same behavior `solve.py`'s existing `certified_limit` kind (`solve.py:110-111`) already gives, generalized from "only reachable via a string `seq`" to "reachable from any `Expr`." |
| derivative/integral/sum = continuum limit | `Derivative`/`Integral`/`Sum`/`Product` are finite exact **descriptions** (nodes), not continuum-limit values. `Sum` with `upper = Infinity(+1)` is representable and printable but stays unevaluated unless a `certified.*` bridge closes it (e.g. `certified.geom_series` for a geometric `Sum`, matching the existing `geometric_series` kind, `solve.py:81-82`, which is already the one `Th_coqc`-backed instance of exactly this pattern). |
| angle/degree, π/e/φ as numbers | Out of this pillar's scope (geometry/constants pillars) — Kernel's `Symbol`/`Const` types are what those pillars build symbolic angle-free geometry ON, not where the angle replacement (Def 4.2a overlap-fraction) is implemented. |

**Domain-unsafe rewrite discipline (the actual point of this pillar):** `sqrt(x**2) → abs(x)`, `log(a*b) → log(a) + log(b)`, `(x**a)**b → x**(a*b)` are each registered in `rewrite.py`'s table as `(pattern, domain_requirement)` pairs. `rewrite_safe(e, name)`:
1. computes `domain_of(e)` / `assumptions_of(subexprs)`,
2. if the domain requirement is **entailed** → applies the rewrite,
3. if **entailed false** or **undecided** → returns a `Piecewise` (branch on the condition) or raises `DomainUnsafeRewrite` if no safe branch exists.

This directly closes both gaps the ground map named: the unconditional pow-collapse at `symbolic.py:117`, and the complete absence of log/sqrt splitting (currently unimplemented — "nothing to fix, but also nothing gating them if someone adds them later," ground map §6). Kernel's rewrite table is domain-gated **from day one**, so there is no green-field identity anyone can add later without a gate — the registration mechanism itself requires one.

**Tier mapping into `solve.py`'s existing three-tier vocabulary** (`Th_coqc` / `exact` / `finite_diagnostic`) is unchanged — Kernel operations declare `exact` for provably-terminating rewrites over `QQ` (no per-rewrite Coq proof exists yet, matching the current honest downgrade), and any `HoldError` surfaces as the dispatcher's existing HOLD path (`solve.py:806-810`), never a crash and never a silently-guessed value.

## (f) Top 3 risks + mitigations

**1. Silent domain-unsafe-rewrite regression.** A future contributor adds a new identity to `rewrite.py`'s table (or a new special function's derivative/simplification rule) without wiring the `Domain` gate, reintroducing exactly the class of bug the ground map flagged. *Mitigation:* make registration itself require a `domain_requirement` argument (no optional/defaulted-away gate — a rule with a branch cut or non-injective sub-map registered with `domain_requirement=None` fails at import time, not silently at runtime); add a property-based test (hypothesis-style) that compares `rewrite_safe`'s output against `to_callable`-numeric evaluation at domain-*violating* sample points (e.g. negative `x` for `sqrt(x**2)`) so a regression fails CI immediately, not eventually.

**2. Expression-size / memory blowup breaking the finite-resource discipline.** `expand`/high-order `diff` can grow exponentially; a process-global hash-cons table in a long-running process (`idm/server.py` exists in the module list) can leak memory across requests indefinitely. *Mitigation:* (i) hard `max_terms`/node-count budgets on `expand`/`diff(order=k)` that raise `ResourceBudgetExceeded` (→ HOLD with an explicit "resource ledger exceeded" reason) rather than hang or OOM; (ii) scope the intern/hash-cons table **per request** (or LRU-bounded), not process-global, so `idm/server.py` doesn't accumulate unbounded memory across many requests.

**3. Two-tree world during migration.** `idm/symbolic.py`'s tuple tree is live and called by 6 kinds today, and the repo shows active concurrent development in adjacent areas (`HILBERT_H1_BUILD_SPEC.md`, `HILBERT_MATHEMATICAL_CORE_ROADMAP.md` present at repo root) that could be touching neighboring modules in the same window. *Mitigation:* ship Kernel purely additively (`idm/kernel/` as a new package), provide `from_legacy`/`to_legacy` adapters, re-point only the 6 named `symbolic_*` handler bodies in `solve.py` in the same change, and leave `idm/symbolic.py` importable and untouched (deprecated-not-deleted) until every caller is confirmed migrated — the same posture the repo already uses for `algebra.py` as a thin shim over `tools/aggregate.py`.

## (g) Explicitly out of scope for Phase 1

- **General algebraic-number arithmetic beyond degree 2.** No Sturm-sequence real-root isolation, no general resultant/GCD-based algebraic simplification. `poly_roots` (Durand–Kerner, `solve.py:206-207`, numeric `finite_diagnostic`) is unchanged. `AlgebraicNumber` is constructed only from the existing quadratic-radical path and exact rational roots.
- **A general CAS pattern-matcher / rewrite-rule DSL.** Phase 1 keeps the same explicit-function-table pattern-matching style `symbolic.py` already uses (extended into a registry, not generalized into a Mathematica-style term rewriter).
- **Symbolic (non-numeric-entry) linear algebra.** `Matrix`/`Vector`/`Tensor` are containers in Phase 1. Only exact-`QQ`-entry matrices route to `exact.py`'s existing `determinant`/`inverse`/`rref`/`null_space`/`hermite_normal_form`/`smith_normal_form`/`matrix_exp`. A matrix with a free `Symbol` entry HOLDs on any operation requiring evaluation.
- **Multivariate symbolic integration, symbolic-bound definite integrals, PDE/ODE as nodes.** `Integral`/`Sum`/`Product`/`Limit` are representable (parse/print/substitute/differentiate-through), but only the same single-variable elementary-antiderivative + linear-argument pattern set `symbolic.integrate` already has actually *evaluates* them. Anything else stays an unevaluated `Expr` — itself a valid, useful output, not a failure — or HOLDs when a numeric value (not an expression) is demanded.
- **A compiled/JIT/vectorized evaluation backend.** `to_callable()` is a recursive tree-walk interpreter matching `functions.evaluate`'s current performance class, not a compiler.
- **Complex-analytic symbolic engine.** `transforms.py`'s numeric `mp.mpc` arithmetic is untouched. `ComplexExact` is for exact Gaussian-rational-or-algebraic complex *numbers*, not symbolic `sin(a+bi)`-style complex-analytic rewrites.
- **Assumption inference as theorem-proving.** `Domain`/`Assumptions` is a fixed, small per-node-type rule table, not an SMT solver or constraint propagator. Anything the table can't decide returns `None` (undecided) and the caller HOLDs or emits `Piecewise` — it never attempts a proof search.
- **Migrating the other ~252 non-symbolic kinds onto Kernel.** Phase 1 touches only the 6 `symbolic_*` kinds. `integral`, `derivative`, `ode`, and the rest keep calling `functions.py`/`integrate.py`/`interval.py` exactly as today; their eventual move to `to_callable`/`to_interval_callable` is noted as the seam (§d) but not executed in this phase.
