# Conditional solution objects

# IDM Symbolic Kernel v2 — Pillar: Conditional Solution Objects

**Scope of this document.** One pillar of the shared-kernel redesign: `solve` (in every sense — equations, systems, inequalities, boolean combinations, diophantine, recurrences) returns a **solution object**, never a bare root list. Grounded directly in the current code at `idm/symbolic.py`, `idm/solve.py`, `idm/exact.py`, `idm/interval.py`, `idm/certified.py`, `idm/functions.py` (all paths relative to `information-discrete-math/`). Phase 1 = design + interface contract, not full implementation.

---

## 0. Where this lives

New module **`idm/kernel_solutions.py`**, sitting *above* the existing exact tree rather than replacing anything:

```
idm/symbolic.py   — unchanged: the finite exact tree (Fraction | ('var',n) | ('add',…) | ('mul',…) | ('pow',b,e) | ('func',n,a))
idm/exact.py      — unchanged: Fraction-based number theory / linear algebra primitives
idm/interval.py   — unchanged: mp.iv rigorous enclosures
idm/kernel_solutions.py   — NEW: Condition/Solution/SolutionSet + solve/solve_system/solve_inequality/
                             solve_diophantine/solve_recurrence/verify, built by CALLING the above
idm/solve.py      — _REG handlers for solve-shaped kinds rewritten to call kernel_solutions and
                    serialize the result; registry mechanism itself untouched
```

This keeps the well-tested `symbolic.py` tree/`diff`/`simplify`/`expand` code completely unmodified — this pillar is a *consumer* of that tree, not a rewrite of it. A companion pillar (the domain/assumption rewrite engine — `sqrt(x²)→|x|`, `log(ab)→log a+log b` under assumptions) is explicitly **not** this document's scope; §6(f) marks the exact seam where this pillar calls into it once it exists.

## (a) Data structures

```python
# idm/kernel_solutions.py
from dataclasses import dataclass, field
from enum import Enum
from fractions import Fraction as Q
from typing import Optional, Union

Expr = Union[Q, tuple]        # idm.symbolic's existing tree type — NOT redefined, reused as-is

class Domain(Enum):
    C = "C"          # complex — the default ambient domain unless narrowed
    R = "R"           # real
    Q_ = "Q"          # rational
    Z = "Z"           # integer (diophantine, recurrence indices, periodic-family parameters)

class Tier(Enum):
    TH_COQC = "Th_coqc"
    EXACT = "exact"
    FINITE_DIAGNOSTIC = "finite_diagnostic"
    R_OPEN = "+R-Open"     # completeness blocked by a genuine open/continuum question — kept, not hidden
    DR = "Dr"

class Verdict(Enum):
    OK = "ok"
    CERTIFIED = "CERTIFIED"   # backed by a certified.Readout / interval.py rigorous bound
    HOLD = "HOLD"

class SolutionKind(Enum):
    DISCRETE = "discrete"       # finite list of point solutions
    PARAMETRIC = "parametric"   # family indexed by one or more free integer/real parameters
    INTERVAL = "interval"       # union of intervals (inequalities)
    IMPLICIT = "implicit"       # system collapses to a curve/manifold, not enumerable points
    EMPTY = "empty"
    ALL = "all"                 # identity — every value in the ambient domain satisfies it


@dataclass(frozen=True)
class Predicate:
    """One atomic side condition on an Expr, e.g. ('ne', denom_expr, Fraction(0))."""
    op: str                         # "eq" | "ne" | "gt" | "ge" | "lt" | "le" | "in_domain"
    lhs: Expr
    rhs: Optional[Expr] = None      # unused for "in_domain"
    domain: Optional[Domain] = None # used only for "in_domain"


@dataclass(frozen=True)
class Condition:
    """Boolean-combination tree over Predicates. Owned by this pillar (needed for inequality &
    boolean-combination scope items); a fuller assumption/rewrite engine may later attach richer
    predicates but the tree shape here is stable."""
    kind: str                                   # "atom" | "and" | "or" | "not" | "true" | "false"
    atom: Optional[Predicate] = None
    children: tuple["Condition", ...] = ()

    @staticmethod
    def true() -> "Condition": return Condition("true")
    @staticmethod
    def atom_(p: Predicate) -> "Condition": return Condition("atom", atom=p)
    def __and__(self, o): return Condition("and", children=(self, o))
    def __or__(self, o):  return Condition("or",  children=(self, o))
    def __invert__(self): return Condition("not", children=(self,))
    def tostr(self) -> str: ...                  # pretty-print via SYM.tostr on lhs/rhs


@dataclass
class Solution:
    """One (possibly parametric) assignment of the unknown(s)."""
    values: dict[str, Expr]            # var name -> Expr; may itself reference a param, e.g. {"x": ("mul",[("var","k"),SYM.parse("pi")])}
    domain: Domain = Domain.C
    condition: Condition = field(default_factory=Condition.true)   # side condition this branch requires
    multiplicity: int = 1
    params: tuple[str, ...] = ()       # free parameter names indexing this family (empty = single point)
    param_domains: dict[str, Domain] = field(default_factory=dict) # e.g. {"k": Domain.Z}
    verified: Optional[bool] = None    # None = not attempted
    verification_method: Optional[str] = None
    verification_tier: Optional[Tier] = None   # tier of the VERIFICATION step, independent of the solve tier


@dataclass
class ExceptionalCase:
    """A branch of parameter-space excluded from the generic solving path (e.g. leading-coefficient
    a=0 collapsing a quadratic to linear). MUST be enumerated, never silently dropped."""
    condition: Condition
    description: str
    resolved: bool               # True: this pillar solved the branch too, folded into .solutions
    note: Optional[str] = None


@dataclass
class SolutionSet:
    """THE public return type of every solve-shaped kernel call. Replaces bare root/interval lists."""
    kind: SolutionKind
    variables: tuple[str, ...]
    solutions: list[Solution] = field(default_factory=list)
    exceptional: list[ExceptionalCase] = field(default_factory=list)
    status: Verdict = Verdict.OK
    reason: Optional[str] = None
    tier: Tier = Tier.EXACT
    method: str = ""
    domain_assumed: Domain = Domain.C
    completeness: str = "complete"     # "complete" | "partial" | "unknown" — the no-dropped-roots claim level
    coq_theorem: Optional[str] = None  # set only when tier==Th_coqc and a real formal/ ref exists
```

Design notes:
- `Expr` is *not* a new type — it's literally `idm.symbolic`'s existing tree. No parallel AST is introduced.
- `completeness` is the field that makes the "no dropped roots" guarantee auditable rather than asserted: `"complete"` is only set when an algorithm-specific completeness check passed (§(c)); otherwise `"partial"`/`"unknown"` plus `status=HOLD` or a kept-but-honest `tier=R_OPEN`.
- `INTERVAL` solutions store endpoints inside `Solution.values` as e.g. `{"x": ("interval", lo_expr, hi_expr, lo_closed, hi_closed)}` — no new Expr node kind, just a wrapper tuple convention local to this module.

## (b) Public interface contract

```python
def solve(equation, var: str, *, domain: Domain = Domain.C,
          assume: Condition = Condition.true()) -> SolutionSet:
    """Solve equation (Expr, or a string parsed via SYM.parse) = 0 for var.
    Never raises — internal exceptions become SolutionSet(status=HOLD, reason=...)."""

def solve_system(equations: list, variables: list[str], *,
                  domain: Domain = Domain.C) -> SolutionSet:
    """Solve a system. Linear systems: exact. Nonlinear: substitution-only in Phase 1, else HOLD."""

def solve_inequality(expr, var: str, op: str, *,
                      domain: Domain = Domain.R) -> SolutionSet:
    """op in {'gt','ge','lt','le'}; expr op 0. Returns SolutionKind.INTERVAL."""

def solve_boolean(atoms: list[tuple], combinator: str, var: str, *,
                   domain: Domain = Domain.R) -> SolutionSet:
    """atoms: list of (expr, op) pairs (op includes 'eq'/'ne' too); combinator in {'and','or'}.
    Combines each atom's SolutionSet via Condition algebra (§c.9)."""

def solve_diophantine(equation, variables: list[str], *,
                       form: str = "linear") -> SolutionSet:
    """form in {'linear','pell'}. Nonlinear/general diophantine -> HOLD (Phase 1 scope, §g)."""

def solve_recurrence(coeffs: list[Expr], initial: list[Expr], *,
                      var: str = "n") -> SolutionSet:
    """Linear constant-coefficient recurrence a_k x[n+k]+...+a_0 x[n]=0 given initial values.
    Closed form via characteristic polynomial (built entirely from solve()). Non-constant-
    coefficient/nonlinear -> HOLD."""

def verify(sset: SolutionSet, equation, *, var: Optional[str] = None) -> SolutionSet:
    """Back-substitute every Solution (POINT exactly via SYM._subst+simplify; PARAMETRIC via a
    single symbolic identity check in the free parameter — never per-instance enumeration).
    Mutates .verified/.verification_method/.verification_tier on each Solution in place, returns sset."""

def to_dict(sset: SolutionSet) -> dict:
    """Serialize to the existing idm.solve wire contract: {"kind":..,"status":..,"value":..,
    "tier":..,"method":..}. This is the ONLY function idm/solve.py handlers need to call — it is
    the seam that keeps _REG/_ok/_norm (idm/solve.py:27-51) completely unchanged."""
```

`solve`/`solve_system`/`solve_inequality`/`solve_boolean`/`solve_diophantine`/`solve_recurrence` all accept a string or an already-parsed `Expr` and call `SYM.parse` internally when given a string — matching the existing convention in `idm/solve.py` (e.g. `SYM.parse(p["expr"])` at line 546-547) so callers pass raw problem-dict strings unchanged.

### Kind-handler migration shape (illustrative, not full code)

```python
# idm/solve.py — replaces the current _ssol body (solve.py:545-548)
@kind("symbolic_solve")
def _ssol(p):
    ss = kernel_solutions.solve(p["expr"], p["var"], domain=Domain[p.get("domain", "C")])
    ss = kernel_solutions.verify(ss, p["expr"])
    return kernel_solutions.to_dict(ss)
```

## (c) Key algorithms and complexity

Every algorithm below is built **only** from already-existing primitives (named per §(d)) plus new glue — no new numerical core is introduced.

1. **Polynomial equation, degree 1.** Reuses `SYM.poly_coeffs`/the linear branch of `SYM.solve` (`idm/symbolic.py:277-278`). O(1). **New:** if the degree-1 coefficient is itself a non-constant sub-tree (a symbolic parameter, e.g. solving `a*x+b=0` for `x`), do **not** call the existing code path unmodified — that path silently mishandles a zero/symbolic leading coefficient today (`("pow", a(1), Q(-1))` on `a(1)==Q(0)` falls through `simplify`'s pow-case to an unevaluated `0**-1` node, `idm/symbolic.py:111-118`, rather than erroring or branching). Kernel wraps this: detect non-`Fraction` coefficients and emit two `ExceptionalCase`s (`a≠0 → x=-b/a`, `a=0 ∧ b≠0 → ∅`, `a=0 ∧ b=0 → ALL`) instead of one silently-wrong branch.

2. **Polynomial, exact/rational branch.** `X.rational_roots` (`idm/exact.py:171`, rational-root-theorem trial division: O(divisors(a₀)·divisors(a_d)·d) evaluations, each O(d) via Horner). Gives exact `Fraction` roots only — `completeness="partial"` unless deflation confirms all roots found (Phase 1 does **not** implement squarefree-factorization deflation — flagged as Risk 1, §e).

3. **Polynomial, complex-complete branch.** `AN.poly_roots` (Durand–Kerker, called today at `idm/solve.py:206`), O(iterations·d²). **New required step:** residual check `|p(root_i)| < tol` via `SYM.evaluate`/`F.evaluate` for every returned root, plus an exact Vieta cross-check (Σroots ≈ `-c_{d-1}/c_d`, Πroots ≈ `±c_0/c_d`, both O(d) exact `Fraction` arithmetic) before `completeness="complete"` may be set — otherwise `partial`+`HOLD`. This is what turns "Durand–Kerker returned *something*" into an auditable no-dropped/no-spurious guarantee; it does not exist in the current `poly_roots` handler.

4. **Rational function `p(x)/q(x)=0` with excluded points.** Solve `p=0` via (1)–(3), then for each candidate root evaluate `q` (`SYM.evaluate`); a root coinciding with a zero of `q` is removed from `.solutions` and logged as a *resolved* `ExceptionalCase` ("candidate is a pole/removable singularity, not a solution"). O(d) extra evaluations.

5. **Transcendental equations.** Phase 1 pattern library only: `sin(L)=c`, `cos(L)=c`, `exp(L)=c`, `log(L)=c` where `L` is affine in `x` (reuses `SYM._lin_coeff`, `idm/symbolic.py:243-249`, already used by `integrate`). Produces a `PARAMETRIC` `SolutionSet` with `params=("k",)`, `param_domains={"k": Domain.Z}` for periodic families (e.g. `sin(x)=0 → x=k·π`). Anything outside the pattern library → `HOLD`, `reason="no closed-form pattern in Phase 1 library"`. No Risch algorithm, no general transcendental solving.

6. **Systems — linear.** `X.solve_linear` (`idm/exact.py:145`, exact ℚ Gauss–Jordan, O(n³)) for a unique solution; underdetermined systems reuse `X.null_space` (`idm/exact.py:434`) to build a genuinely `PARAMETRIC` `SolutionSet` (free variables become `params`) instead of the current dead end where `solve_linear` just returns `None`/HOLD (`idm/solve.py:193-194`). Inconsistent → `EMPTY`.

7. **Systems — nonlinear.** Phase 1: substitution-only when one equation is linear in one variable (reduces to case 6 after substitution); otherwise `HOLD` (`reason="no Gröbner-basis/resultant solver in Phase 1"`). A single **numeric candidate** may optionally be attached via `OPT.newton_system` (`idm/solve.py:519-521`) but tagged `tier=finite_diagnostic`, `completeness="partial"` — never presented as the full solution set.

8. **Inequalities (single variable, real).** Find real roots of `f` via (1)–(3) restricted to `Domain.R` (discard non-real roots after residual check), sort, then test sign of `f` on each open sub-interval by exact `Fraction` evaluation at a rational test point (or a certified `IVL.verified_range` sign check, `idm/interval.py:33-39`, when the test point isn't exactly evaluable). O(d log d) sort + O(d) sign tests. Result is `SolutionKind.INTERVAL`; endpoints are exact `Fraction` when the boundary root was exact, or a certified `(lo,hi)` enclosure (never a bare float) when it came from the complex/numeric branch.

9. **Boolean combinations.** Solve each atom independently, then combine via `Condition`: `AND` = interval intersection (`INTERVAL` kind, O(n log n) sweep) or discrete filtering (evaluate every other atom at each candidate point, O(n·m)); `OR` = union/concatenation; `NOT` = complement within the stated ambient `domain` (finitely describable — e.g. `ℝ \ {finite point set}` is expressed as `x≠r₁ ∧ x≠r₂ …`, not enumerated) — `HOLD` only if the ambient set itself isn't finitely describable (out of Phase 1's target cases).

10. **Diophantine.** `linear`: `X.diophantine_linear` (`idm/exact.py:380-384`, extended Euclid, O(log min(a,b))) → `PARAMETRIC` `SolutionSet`, `params=("t",)`, `param_domains={"t": Domain.Z}`. `pell`: `X.pell` (`idm/exact.py:402-411`, continued-fraction of √D, O(period(D))) → fundamental solution plus the standard Pell recursion as the parametric generator. General/nonlinear diophantine → `HOLD` (§g).

11. **Recurrences (linear, constant-coefficient, order k).** New algorithm, built from #2/#3 + #6: form the characteristic polynomial from `coeffs`, call `solve()` on it (reuses the entire polynomial pipeline, including its `completeness` bookkeeping), then fit the linear-combination coefficients `c_i` (accounting for root multiplicity via extra `n^j·r^n` terms) against `initial` via `X.solve_linear` — O(k³) for the fit + the polynomial-solve cost above for the roots. Non-constant-coefficient or nonlinear recurrences → `HOLD` (§g); no generating-function machinery in Phase 1.

12. **Verification.** Point solutions: `SYM._subst` + `SYM.simplify` (`idm/symbolic.py:300-306`, `100-165`) — exact, tier unchanged if it collapses to `Q(0)`/`True`; else one numeric check via `SYM.evaluate`/`F.evaluate` at raised `mp.mp.dps`, `verification_tier=finite_diagnostic`. **Parametric families are verified once, symbolically, treating the parameter as a free symbol** — e.g. substitute `x=x0+t·dx, y=y0+t·dy` into `a·x+b·y−c` and simplify to the identity `0` in `t` — never by enumerating instances of `t`, which would be an unbounded non-readout loop. This is the single most important readout-first constraint on this pillar (§e).

## (e) Alignment with readout-first tiers, and where HOLD is returned

- **Nothing in this pillar computes with a float, a continuum limit, or an unbounded loop.** Every `Solution.values` entry is an `Expr` (exact `Fraction`-rooted tree) or a certified `(lo,hi)` enclosure from `interval.py` — never a bare Python `float`.
- **Parametric families are the readout-safe way to express "infinitely many" solutions**: `x = k·π, k∈ℤ` is a *finite* closed-form readout (one tree + one parameter-domain tag), not an enumeration to infinity. Verifying such a family (§c.12) is done by one symbolic identity in the free parameter — attempting to verify by looping over instances of `k` would itself be exactly the non-readout ∞-injection the discipline forbids, so `verify()` is required to detect a `Solution.params`-nonempty case and refuse the per-instance-loop path.
- **`completeness` makes "no dropped roots" falsifiable rather than asserted**: `"complete"` requires a positive check (residual + Vieta for polynomials, exact deflation for linear systems, exhaustive pattern match for the transcendental library); anything else is `"partial"`/`"unknown"`.
- **HOLD is returned, never a crash or a silently wrong answer, when:**
  - the equation isn't polynomial and doesn't match the Phase-1 transcendental pattern library (§c.5);
  - Durand–Kerker fails the residual/Vieta check (§c.3);
  - a nonlinear system has no substitution path (§c.7);
  - an inequality's boundary can't be bracketed rigorously (§c.8);
  - a diophantine equation is neither linear nor Pell form (§c.10);
  - a recurrence has non-constant or nonlinear coefficients (§c.11);
  - a `NOT` combinator's ambient complement isn't finitely describable (§c.9);
  - any internal Python exception occurs — every public function in §(b) wraps its body in a `try/except` that converts to `SolutionSet(status=Verdict.HOLD, reason=f"{type(ex).__name__}: {ex}")`, mirroring the existing outer-dispatcher discipline at `idm/solve.py:807-812`, but done **inside** `kernel_solutions` too so these functions are safe to call directly, not only through `_REG`.
- **`Tier.R_OPEN`** is reserved for the rare case where partial results are trustworthy but completeness is blocked by a genuine open question (e.g., "are there other real roots of this transcendental equation beyond the ones the pattern library found?") — the found solutions keep their own tier; only the *set's* completeness claim is marked open. This is deliberately distinct from `HOLD` (which withholds a value) — `R_OPEN` ships the honest partial value with the gap named.

## (f) Top 3 risks + mitigations

1. **Risk — the completeness guarantee for polynomial roots is currently unenforced.** `AN.poly_roots` (Durand–Kerker) and `X.rational_roots` (rational-root theorem) can both silently under- or (with numerical clustering) double-count roots today; nothing checks. **Mitigation:** the residual + exact-Vieta cross-check in §c.3 is made a *hard requirement* to set `completeness="complete"` — this is new code but built from primitives that already exist (`SYM.evaluate`, exact `Fraction` arithmetic), not a new numerical method.

2. **Risk — parametric solutions could regress into ad hoc strings**, losing the type discipline this whole pillar exists to add (e.g. representing `x=kπ` as a formatted string rather than a typed family). This would also tempt a `verify()` implementation into the per-instance non-readout loop warned about in §(e). **Mitigation:** `Solution.params`/`param_domains` are first-class dataclass fields, not string flags, and `verify()`'s contract explicitly forbids per-instance enumeration for any `Solution` with non-empty `params` — enforced by a guard clause, not a convention.

3. **Risk — two incompatible "give up honestly" vocabularies already coexist** (`certified.Readout`'s `CERTIFIED`/`HOLD` vs. ad hoc `{"status":"HOLD","reason":...}` dicts used throughout `solve.py`/`interval.py`), and a naive `SolutionSet.status` design could add a *third*. **Mitigation:** `Verdict` is deliberately built as the superset `{ok, CERTIFIED, HOLD}` so a `Readout` can be wrapped directly (`Verdict.CERTIFIED` when a `Readout.status=="CERTIFIED"` backs a solution) without inventing new words; `to_dict()` is the single seam that serializes back to the existing wire format, so no repo-wide status-vocabulary migration happens in Phase 1 — only the handful of kinds this pillar touches change internally.

## (g) Explicitly OUT of scope for Phase 1

- General nonlinear polynomial systems (Gröbner bases, resultants, cylindrical algebraic decomposition) — `HOLD` only, no partial nonlinear-system solver beyond single-substitution cases.
- Nonlinear/higher-order/non-constant-coefficient diophantine equations beyond linear + Pell (no general quadratic-form or Pythagorean-triple-style solver).
- Non-constant-coefficient or nonlinear recurrences; no generating-function closed-form machinery.
- General transcendental equation solving beyond the fixed Phase-1 pattern library (§c.5) — no Risch algorithm, no arbitrary closed-form search.
- Multivariate inequality *regions* beyond the single-variable interval case and simple linear systems — no general semialgebraic-set / CAD support.
- A general domain/assumption **rewrite** engine (`sqrt(x²)→|x|`, `log(ab)→log a+log b`, `(x^a)^b` splitting under assumptions) — that is a separate pillar; this one only *consumes* a `Condition`/`Domain` at the moment it must gate a candidate solution (e.g. discard an extraneous root introduced by squaring), it does not implement general identity rewriting.
- Fully symbolic-coefficient closed-form solving (e.g. Cardano's formula for a cubic with symbolic `a,b,c,d`) — Phase 1 requires numeric (`Fraction`) polynomial coefficients; the only symbolic-coefficient case handled is the degree-1 zero/nonzero `ExceptionalCase` split (§c.1).
- No visualization/GUI of interval solution sets — output stays `SolutionSet`/`to_dict()` data, consistent with every other kind in `idm/solve.py`.
- Performance/production hardening (memoization across repeated `solve()` calls, large-system scaling) is deferred.
